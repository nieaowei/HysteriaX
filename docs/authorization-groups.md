# 授权组

在「用户」页面的工具栏中切换「用户 / 授权组」。授权组同时包含用户和节点；每位成员获得组内所有节点的访问权限。用户属于多个组时，权限取并集，同一个节点只出现一次。

## 管理方式

在授权组页填写名称创建空组，再通过「管理用户」「管理节点」分别添加成员和节点。后续通过「管理用户」和「管理节点」批量调整。授权组页采用左右布局：左侧选择授权组，右侧详情分为「成员 / 节点 / 记录」，成员表格支持名称或 ID 搜索、状态筛选和排序。分隔线可拖动调整左栏宽度，右侧会填满剩余空间。长用户 ID 会中间省略，悬停可查看完整值。双击成员或使用右键菜单可打开用户详情。用户页的「管理授权组」用于调整单个用户的所属组；节点权限旁显示所有来源组。

创建、删除授权组以及成员、节点、名称和用户所属组修改统一提交异步任务，不按变更大小分流，也不需要预览或影响确认。所有写接口返回 HTTP 202 和 `{job_id,resource_id,status:"queued"}`；保存成功表示任务已持久化，后台按页逐步生效，任务成功表示所有分页均已完成。创建时预留组 ID 和名称，后续关联变更仍须等待创建任务结束。

客户端显示排队、执行、成功或失败，可查看任务、失败原因并重试。任务按索引游标读取本次变更项，关系写入、分配、身份和断连任务每页最多 256 项；每页业务变更与游标一起提交。失败时保留已提交分页及撤权屏障，重启或关联重试从已提交游标继续。同一组或用户已有未完成任务时返回 409；相关组和用户所属组的冲突编辑也会被拒绝，避免覆盖尚未完成的意图。

撤权请求提交时写入精确的授权来源排除记录。认证和订阅会立即排除这些来源；若另一个组仍提供同一节点权限，访问继续保留。后台删除最后一个有效来源对应的分配并提交断连任务。任务失败时排除记录保留，不恢复旧权限。在线连接需要后台断连执行后才结束。任务不会在 HTTP 请求内生成密码或签名证书。

授权预览界面、接口和令牌协议已移除。`0003_remove_authorization_previews.sql` 删除预览表及全部旧记录，现有授权关系、凭据和撤权需求保留。执行此维护迁移前需要停止全部 API，使用配套客户端和服务端。

撤权按节点合并为一个活跃任务，用户需求保存在 `kick_requests`。每批最多处理 200 人，经节点本地接口批量断连并确认在线状态；每轮最多处理 10 批后释放执行权，继续使用原任务 ID。已完成用户的进度逐批保存，重新授权或新增撤权通过代次校验处理。

连接密码属于用户：一个用户在全部授权节点上使用同一份密码，创建用户时生成；`node_assignments` 只保存访问分配。新增、移除授权不改变密码。认证必须同时满足用户资格、用户密码、节点分配和当前有效授权来源；用户密码轮换只更新一行用户凭据，并对全部已分配节点提交断连请求。

需要 mTLS 的节点仍使用用户自己的证书。后台授权任务新增有效分配时创建所需共享身份和签发任务；已发布 CA 由身份维护任务签发，准备中的代次由轮换任务处理。授权任务成功不代表全部证书或断连已完成。缺少可用证书的节点暂时不进入订阅，证书就绪后刷新订阅。不同用户不共享密码或证书。

用户自身的停用、到期、流量额度限制仍然生效。组没有独立流量额度、有效期或嵌套关系。

## 大量成员管理

授权组目录每页显示 50 组；组内成员和节点每页显示 100 项，搜索、状态筛选和排序由服务端执行。目录及组详情只返回元数据和人数、节点数，不再附带完整 `user_ids`、`node_ids`。

「选择」菜单只选择当前页；跨搜索、筛选和分页保留显式选择，「仅显示已选」用于检查选中项。成员、节点编辑采用增量草稿，仅保存明确添加或移除的 ID；未访问页面不会参与变更。候选成员、候选节点通过服务端筛选，打开授权组页面和编辑窗口不会预加载全部用户或节点。

用户的「选择授权组」弹窗也使用服务端搜索与分页，翻页保留选择，提交用户所属组时仍按完整已选组集合保存。

点击「添加成员」进入非成员列表，多选后点击「添加所选」加入草稿。在成员表格中多选后可批量移除；右键菜单也提供移除入口。详情页的批量移除会打开草稿编辑窗口，不会立即撤权。

编辑窗口提供「成员 / 添加成员 / 仅看变更」三个视图。在变更视图中可选中人员撤销单项或多项修改。关闭时点击「取消」丢弃整个草稿。

点击「保存授权组」提交草稿。服务端在短事务中校验版本、保留新版本并保存任务及撤权屏障；后台按增量计算有效权限并更新分配。版本冲突或目标正在处理时保留草稿并报告错误。所有授权变更均不生成预览记录，也不需要预览令牌。服务端和客户端需配套更新。

## 数据库基线

当前版本仅支持新建空库，不再将旧版个人节点分配自动转换为授权组。通过授权组创建和修改节点权限；服务端和 macOS 客户端需使用配套版本。旧安装应使用匹配的旧镜像和数据库，兼容边界见 [安装指南](installation.md#database-baseline)。

## 局部更新接口

`POST /api/v2/authorization-groups` 只接受 `name`，创建版本为 1 的空组。

`PATCH /api/v2/authorization-groups/{id}` 必须携带 `expected_revision`，其余字段均为可选：

- `name`：新名称。
- `add_user_ids` / `remove_user_ids`：本次添加、移除的成员。
- `add_node_ids` / `remove_node_ids`：本次添加、移除的节点。

省略字段保持原值；空数组不清空关系。同一个 ID 不能同时添加与移除；至少提交一项变化。重复 ID 会去重，重复添加已有关系或移除不存在关系不会造成重复记录。版本过期返回 409，不覆盖其他管理员修改。

旧的完整替换 `PUT` 已移除；请求中的 `user_ids`、`node_ids` 被拒绝。只改名称的示例为 `{"expected_revision": 1, "name": "新名称"}`；移除成员的示例为 `{"expected_revision": 2, "remove_user_ids": ["user-id"]}`。

创建、改名、关系修改和删除共用 `authorization-change` 任务。只改变一名成员时只处理该成员与相关节点，只改变一个节点时只处理该节点与相关成员。后台通过索引查询有效来源、批量插入及删除差集，不读取完整用户—节点矩阵，也不在应用内构造笛卡尔积。

## 本次升级

停止全部旧 API 后，使用测试环境原有主密钥及数据库地址执行 `scripts/migrate-async-authorization.sh`。它调用 `--migrate-only`，应用 `0005_async_authorization.sql` 并补齐没有连接密码的用户，不启动后台任务或联系节点。

已有用户按节点 ID 排序保留一份现有密码作为用户级密码，其他节点的旧密码失效；没有旧分配的用户会生成新密码。授权关系和分配保留，分配表中的密码字段删除。升级后须配套更新客户端并刷新订阅。迁移工具可在中断后重新运行，不覆盖已生成的用户密码。

## 分页读取接口

- `GET /api/v2/authorization-groups`：返回 `{items,total,page,page_size}`，支持 `q`（名称或 ID 的字面量、不区分大小写子串）、`sort=name|created_at|updated_at`、`order=asc|desc`。
- `GET /api/v2/authorization-groups/{id}`：只返回组元数据、`user_count` 和 `node_count`，不再返回关联 ID 数组。
- `GET /api/v2/authorization-groups/{id}/users`：返回轻量成员 `{id,name,enabled,expires_at}` 的分页结果及 `revision`；支持 `q`、`member=true|false`（默认 true，false 查询未加入的候选用户）、`enabled`、`sort=name|id|expires_at`、`order`。
- `GET /api/v2/authorization-groups/{id}/nodes`：返回轻量节点 `{id,name,state}` 的分页结果及 `revision`；支持 `q`、`member`、`sort=name|id|state`、`order`。

所有列表默认 `page=1&page_size=50`，`page_size` 限制为 1–200；页码必须大于零。超出范围时返回最后一页，空结果返回第 1 页。名称排序使用名称小写、原名称和 ID 稳定排序，其余排序也以 ID 决胜；到期时间为空的成员排在最后。计数、页内容及组版本在同一数据库读快照内读取。成员和节点接口不返回用户权限图、SSH 配置或凭据。

本次读取协议与旧客户端不兼容，服务端与客户端必须配套更新。本次升级包含数据库迁移；现有授权关系保留，部署后重新打开旧客户端中的编辑窗口并刷新订阅。

凭据中心沿用 `user_credential` 类型，每个用户展示一条连接凭据（含尚未分配节点的用户），名称跟随用户，记录 ID 不受授权节点增删或密码轮换影响。当前引用对象数为该用户已落库的节点分配数量；异步撤权执行期间可能尚未清理完成，认证仍以实时有效来源校验为准。点击“管理用户”可查看分配并使用原有轮换入口。目录只展示摘要，不额外保存密码或创建通用凭据版本。

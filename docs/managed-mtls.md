# 托管 mTLS 与升级

节点支持 `mtls.mode=off` 或 `managed`。托管模式选择凭据中心的 CA 身份，系统管理用户及节点探测证书；服务端证书可使用手动 TLS 或节点独立 ACME，手动 TLS 证书仍可正常导入。

## 身份与访问控制

一个用户在同一 CA 身份下复用证书和私钥；不同用户、不同 CA 凭据 ID 使用不同身份。客户端证书期限由 CA 策略与 CA 有效期决定，与账号到期时间分开。账号停用、到期、超额及撤权继续阻止认证并按现有机制断连；恢复账号后自动补齐可用证书。

共享 CA 形成共享 TLS 信任域。当前上游认证回调只提供连接密码，服务使用“受信客户端证书 + 节点连接密码”两层检查，无法把 TLS 证书身份绑定到具体账号。不要把共享 CA 当作租户隔离机制。

用户普通重新签发影响该 CA 下所有相关节点，需要客户端刷新订阅。普通续期不踢连接；旧证书仍可使用至自然到期。密钥泄漏时应停用账号、轮换连接密码和订阅令牌并断连；CA 泄漏时更换 CA 身份并一次切换。本期无 CRL/OCSP 或单张证书即时吊销。

## CA 与维护

CA 身份可以生成或导入。导入需要匹配私钥和完整证书链；仅把选定签发 CA 加入节点信任，不自动信任其上级根 CA。新绑定 CA 必须剩余超过 30 天。

客户端策略为 `client_validity_days`（1–365，默认 180）和 `renew_before_hours`（至少 1 小时且小于有效期，默认 720）。策略使用独立修订号，修改不创建 CA 密钥版本，不部署节点，影响后续签发。需要立即替换时使用用户按 CA 重新签发。节点探测证书独立于用户，为 7 天有效、提前 48 小时续期。

生成的 CA 提前一年自动轮换；导入的 CA 需要管理员提供替代材料。发布新版本时：

1. 所有当前目标、实际部署和未确认远端引用节点部署新旧信任，并用目标 CA 探测证书验证。
2. 分批为所有当前有访问资格的用户准备共享版本，最终事务重新检查节点和用户，再发布新签发代次。
3. 切换节点探测身份，完成本轮。旧叶证书最晚到期后加 5 分钟再清理旧信任。

任一离线或失败节点都会阻止共享证书发布。已成功节点保留双信任；在批次或任务入口重试失败操作。修改目标配置为关闭或其他 CA 不会立刻移除实际部署的发布门槛，必须完成远端切换。

新轮换可在上一轮发布及探测切换完成后启动，无需等待旧证书到期。清理任务重新计算当前信任并集，保留后续轮换所需代次。退役 CA 不再签发新材料。

阻塞状态返回节点、用户准备数、旧材料期限及错误。30/14/7 天和到期提醒复用客户端通知机制；正常自动续期不要求人工操作。旧材料到期后可能不可连接，不能依靠轮换任务保留可用性。

## 远端故障与回滚

部署切换期间节点进入 `activating`，暂时过滤用户认证和订阅，只允许绑定当前部署任务的短期探测令牌。无法确认远端结果时保持 `recovery_required`。显式恢复同步会核对已确认配置或精确保存的未确认激活标记及摘要；未知远端状态需要先排查，系统不会盲目覆盖。

历史回滚固定精确 CA、信任和探测材料，同时重新检查当前用户权限及有效共享证书。历史证书过期、废弃或新用户缺少兼容身份时，回滚会在 SSH 修改之前拒绝。请创建新配置并同步。普通历史回滚不会恢复旧权限，也不会重新启用退役 CA 签发。

## 破坏性升级

服务端和 macOS 客户端必须配套升级。当前管理 API 使用 `/api/v2`；写请求需携带稳定的 `Idempotency-Key`。以下记录托管 mTLS 的一次性破坏性转换，不保留旧用户证书绑定和个人节点分配接口。完整切换顺序见 [安装指南](installation.md#management-protocol-2-upgrade-0034)。

升级前按照 [备份与恢复](backup-restore.md) 创建已验证数据库备份，并单独保存主密钥及旧镜像。先在恢复副本上运行新镜像的 `--migrate-only`，核查结果后再切换服务。迁移在 workers/API 启动之前运行：

- 保留账号、授权组、节点、订阅地址、连接密码、流量、SSH 和非用户客户端凭据。
- 丢弃旧用户 mTLS 绑定、用户客户端证书及相关作业/预览；不尝试解密或校验即将丢弃的旧用户材料。仍被其他功能引用的材料保留并校验。
- 废弃含旧 mTLS 的历史回滚快照。当前目标或实际部署任一启用旧 mTLS 的节点进入 `needs_configuration`，阻止用户认证和订阅，持久化排队断连；离线节点恢复可信 SSH 后继续断连。
- 只有历史启用旧 mTLS、当前目标和实际部署均关闭的节点不会阻断当前服务；空或 null 的旧 clientCA 字段也不会被当作启用。
- 重置、保留格式转换及 TLS 凭据整理在同一事务提交。保留材料损坏时回滚，不留下部分清理。迁移标记保证重启不重复清理新托管身份。

待配置节点需要显式选择关闭或有效托管 CA，保存新配置并完成恢复部署。省略 mtls 字段不能自动降级为关闭。远端安装标记与注册信息保留，仍可执行 SSH 检查、删除及显式恢复操作。

在本地构建容器镜像并推送或加载到服务器，再用固定镜像标签启动。不要在服务器执行源码构建。若需要回退旧服务，必须恢复升级前数据库和匹配主密钥，同时使用旧镜像；旧协议材料无法通过新 API 重新导出。

迁移副本可通过 `scripts/verify-managed-mtls-upgrade.py` 验证两种旧凭据格式，
并用 `scripts/verify-credentials-migration.py` 独立核对实际升级前后副本。
真实旧版部署、离线会话、恢复部署及匹配备份回退可在隔离 Docker 环境中运行：

```sh
HYSTERIAX_UPGRADE_IMAGE=hysteriax-server:<本地构建标签> \
  uv run --with-requirements scripts/requirements-test.txt \
  python scripts/verify-managed-mtls-upgrade-live.py
```

此脚本使用固定旧镜像建立旧协议数据，并使用新镜像完成升级；最后恢复旧数据库、远端快照和旧镜像，确认旧订阅实际转发。它创建并清理独立数据库、网络和节点容器，不使用生产数据库。低内存服务器的备份恢复演练应在独立环境执行，避免与生产 PostgreSQL 争用资源。

托管信任已部署或远端结果未确认时，不能通过“仅移除记录”绕过 CA 轮换门槛。先恢复 SSH 并卸载远端服务，或完成关闭/改绑。没有任何已部署或潜在远端信任引用的未部署节点仍可取消。SSH 检查成功改变连接状态，不代表已证明卸载。

## 节点独立 ACME（0003）

ACME 可与 `mtls.mode=managed` 共用。公共配置仍使用 `acme` 和独立的 `mtls` 策略，禁止手写 `tls.clientCA`；管理服务在部署或预览时将其编译为节点托管证书路径，再生成客户端 CA 文件。全部域名共同签发一张 SAN 证书，任一域名验证失败都会阻止整张证书的续期。仍使用原版 Hysteria v2.12.3。

已有节点仅在显式部署、同步或回滚时迁移。正常续期由节点 `hysteriax-acme.service` 自行执行，不重启 Hy2、不增加节点配置修订，也不重发用户证书或刷新订阅。CA 信任轮换仍遵循原有激活、探测和恢复流程。

节点详情中的 ACME 状态来自最后一次 SSH 观测，管理服务离线时节点仍继续维护证书。状态超过两分钟未更新会显示陈旧。恢复使用现有同步入口；组件会保留并遵守重试时间及 CA 的 Retry-After，不提供强制签发接口。

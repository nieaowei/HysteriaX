# 授权组与用户页 Toolbar Tab 实施计划

## 目标与已确认决策

- 在现有用户页工具栏中用「用户 / 授权组」tab 分开管理，侧栏保持用户入口。
- 一个组同时维护用户集合和节点集合，组成员持续继承组节点权限；用户可以属于多个组，权限取并集。
- 统一使用组授权，关闭个人直接分配；用户自身启停、到期和额度继续生效。
- 首版完整支持 mTLS，个人凭据独立绑定到用户—节点，不共享组证书。
- 旧用户按完全相同的节点 ID 集合合并为迁移组；空用户不入组。保留全部密码、证书、订阅和流量。
- 不添加组嵌套、组额度、组到期或个人排除规则。本次不部署服务。

## 页面与交互

- 原生工具栏 segmented Picker，默认用户；窗口保存 tab，各页独立保存搜索、选择和排序。
- 从概览/凭据跳转用户时切回用户；从授权来源跳转组时选中目标组并清除阻挡目标的搜索。
- 授权组沿用上下分栏，上方表格显示名称、用户数、节点数、更新时间；下方详情提供编辑名称、管理用户、管理节点、删除。
- 创建组可选择用户/节点，也可以创建空组。选择器支持搜索、多选、已选筛选和选择筛选结果；取消丢弃选择器草稿，完成应用选择。
- 所有写入先显示服务端计算的新增/撤销权限预览；撤销只针对失去最后一个来源的连接，删除组同样预览影响。
- 用户详情显示所属组和有效节点的全部授权来源，保留证书管理；以管理授权组替换个人分配。
- 新用户创建成功后再进入加入组流程；取消/失败时保留无节点权限的用户。旧服务继续使用原个人分配流程。
- 普通节点只需选择；mTLS 节点按新增用户—节点逐项选择个人凭据，选择后重新预览。提交结果展示撤权任务状态、复制订阅入口和按需展开的密码。
- 编辑和结果区域可滚动，操作栏固定；并发失败保留草稿，重新读取 revision 后可重新预览。

## 服务端、数据与 API

- 新增授权组、组用户、组节点以及短期预览记录；包含 revision、时间戳、外键、关系唯一约束及现有写入序列锁。
- `node_assignments` 是组权限的有效结果，继续承载连接密码和个人 mTLS 绑定供认证、订阅、流量及凭据功能读取。
- 在单个事务内更新组关系、协调有效权限、增加 revision、写审计、入队撤权任务。新增来源不轮换已有凭据；失去最后来源才删除有效记录。
- 新授权创建独立连接凭据；重新授权清除旧的组撤权原因，保留其他限制原因。用户/节点删除清理关系并更新受影响组 revision。
- mTLS 检查凭据类型、归属、版本及归档状态；错误整笔回滚。多组共享同一用户—节点有效绑定。
- 预览 token 绑定完整提案和相关用户/组 revision、节点配置、个人凭据状态；10 分钟过期，单次使用。提交重算差异和守卫，过期/并发改变时拒绝。
- 新增 `/api/v1/authorization-groups` 列表/创建及 `/{id}` 详情/PUT 更新/DELETE；删除返回 JSON 变更回执。
- 新增组创建、更新、删除 preview 和用户所属组 preview/PUT 更新接口。回执包含影响数量、新建连接凭据及撤权任务 ID。
- 用户响应增加所属组，节点分配增加全部来源组，节点响应增加 `mtls_required`。迁移组 ID 可以是非 UUID 字符串。
- 旧个人分配 POST/DELETE 明确拒绝，保留证书更新、凭据轮换和查询。`/version` 增加 `authorization_groups` 能力。
- 更新 OpenAPI 与 Swift 生成器/模型。客户端按服务能力选择新旧流程；组加载失败独立显示，不清空用户数据。

## 迁移与升级

- 迁移文件 `0010_authorization_groups.sql` 按排序节点集合建「迁移授权组 N」，不改现有有效记录、不轮换令牌、不触发撤权。
- 不设置会使现有迁移组无法编辑的任意成员数量上限，沿用请求体限制。
- 升级前备份数据库，先升级服务端再升级客户端；旧客户端组相关写入提示升级。
- 回退使用升级前备份，不能让旧服务写入组授权数据库。
- 后续如果部署，按仓库要求在本地构建容器镜像并推送服务器。

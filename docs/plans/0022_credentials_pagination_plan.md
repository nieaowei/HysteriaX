# 0022 凭据页服务端分页

日期：2026-10-09

## 目标

参照已有列表分页，为凭据页增加分页、总数显示和全目录筛选/排序。运营与用户分类、托管及合成凭据、归档/撤销状态、引用计数和详情发布流程保持可用。

## 实施步骤（已完成）

1. 新增 `GET /api/v1/credentials/page`，返回 `{ items, total, page, page_size }`。
   - 默认第 1 页、每页 50 条，允许 1–200 条；非法参数返回 400，越界页码返回最后一页，空结果返回第 1 页。
   - 支持全部/运营/用户分类、类型和名称搜索；分类按 owner_user_id 判定，归档与撤销条目仍保留。
   - 统一目录包括托管凭据、管理员 Token、订阅 Token 和用户连接凭据。复用原目录装配与当前引用去重逻辑，在服务端聚合后执行筛选、稳定排序和页切片。
   - 名称、类型、状态和创建时间可排序，名称/ID 作为稳定后续排序字段；创建时间按实际时间解析，覆盖含/不含小数秒的情况。
   - 所有目录来源及引用统计在同一个只读、可重复读事务、同一连接上读取。单连接池也可执行。
2. 更新 OpenAPI、生成器、Swift DTO/端点和凭据 Store 的分页读取方法。
   - 原完整凭据目录接口保持不变，继续供节点配置、DNS、SSH、mTLS 等选择器及离线快照使用。
   - 本次无数据库迁移，沿用当前 schema 14。
3. 凭据页增加上一页/下一页、25/50/100 条选项、总数和页码、加载提示、错误显示和失败重试。
   - 名称、类型、状态列排序在服务端应用；分类/类型/搜索/排序/每页条数改变后回到第一页。
   - 翻页清除旧选择；创建凭据完成后回到第一页并保留原分类切换逻辑。
   - 页和详情请求均检查取消及请求标识，服务切换清空页缓存和选择，防止旧响应覆盖当前页面。
   - 离线时对已有完整目录分页，类型选项仍基于完整分类目录。
4. 补充混合目录、归档及引用、安全字段和客户端网络回归，更新中英文文案和 UI 夹具。
5. 本地构建 amd64 镜像，上传验证后部署 Server1，执行公网混合目录验收。

# 0032 概览节点监控分页与搜索

状态：已实施并部署（2026-10-15）。

## 实施

1. 新增 GET /api/v1/overview/nodes，使用 page、page_size、q；默认 20 条，每页上限 200，越界页夹到末页，空结果返回第一页。名称、节点 ID、公网及 SSH 地址按大小写不敏感的字面子串搜索；百分号、下划线和反斜杠保留字面语义。先 SQL 过滤、排序和分页，再批量读取本页最新采集/探测记录；不解密节点配置或生成 YAML。
2. 名称、原名、ID 提供稳定次序；COUNT 和分页数据处于同一个只读可重复读事务。迁移 0027 增加对应的 pg_trgm 搜索索引。
3. 将在线与探测状态映射提取成公共函数，概览汇总与分页保持相同的采样时效、部署版本校验、失败状态和连接计数语义。
4. 从 /api/v1/overview 移除全量 nodes 数组，新增全局 healthy_nodes；汇总的健康数、在线用户、连接数和覆盖率始终按全部节点计算，不跟随分页或搜索改变。该响应调整是明确的破坏性变更，不保留旧数组；API 命名空间仍为 /api/v1，不新增 /page 路径。
5. 概览“连接与质量”的节点监控卡片增加搜索框、上一页/下一页及每页 10/20/50/100/200 条选择。搜索和每页条数变化回到第一页；搜索输入防抖 250 ms。窄窗口分页控件可换行。
6. 使用共享客户端分页缓存：再次进入先显示同条件缓存，同时请求更新；页面持续显示时随全局刷新更新采集数据。切换服务清理状态，取消过时请求，保留失败前已有内容；Inspector 从最新分页快照读取节点状态。
7. 后端该接口响应缓存 3 秒，依赖节点、在线、探测等相关版本；概览响应键增加结构标识，避免旧 Redis 响应影响新 DTO。更新 OpenAPI、Swift 生成器及生成模型、客户端/后端测试和验证脚本。

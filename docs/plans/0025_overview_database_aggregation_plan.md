# 0025 概览数据库聚合查询

日期：2026-10-11

## 起点与目标

先将现有分页接口改造、客户端适配及部署记录提交为 `575c5a6`（`refactor(api): consolidate collection pagination routes`），然后实施本计划。

概览直接查询统计结果、监控字段和告警候选记录，删除节点/用户分页遍历及逐节点数据库查询。保留概览统计含义、监控列表和告警规则，不新增全量列表接口。

## 实施步骤（已完成）

1. 新增 `overview/summary.rs`，在一个 `REPEATABLE READ, READ ONLY` 事务中执行 6 个业务查询。
   - 节点数量与状态：`GROUP BY state` 返回状态数量，并据此得到节点总数。
   - 节点监控：读取轻量 `NodeReading`；批量聚合未关闭采样缺口、撤权任务和有效套餐告警，再关联最新在线采样、最新代理探测及对应修订号的探测状态。
   - 用户告警：只读取启用且七天内到期或已耗尽额度的用户，返回 ID、名称、到期/额度/用量及更新时间。
   - 额度排行：SQL 使用有效用量和精确 `numeric` 比例排序，仅返回前 5 个节点 ID；比例相同按原有名称/ID 顺序打破平局。
   - 任务统计：聚合排队、运行及最近 24 小时失败数量。
   - 重试提醒：保留原递归重试链查询，成功叶节点消除提醒，失败叶节点替换祖先提醒，进行中/取消的尝试保留提醒。
2. 查询完成后提交只读事务，再装配概览响应。节点和用户循环不再访问数据库。
   - 所有判断使用同一个时间点，最新在线采样遇到时间相同时按 ID 降序选取，避免选择不确定。
   - 在线用户跨节点去重、连接统计、监控新鲜度、告警文案和严重程度继续在 Rust 中处理。
   - 不读取节点 SSH/部署配置、凭据、配置资源或用户授权目录，不解密配置、不渲染 YAML。
3. 在 `node_limits.rs` 提取 `PackageReading` 和纯计算函数 `snapshot_from_reading`。
   - 节点详情与概览共用到期限制、月度重置的有效用量、套餐采样新鲜度、撤权失败/等待数量等规则。
   - 概览批量提供数据，详情沿用原有读取入口。缺少套餐记录时保留原有默认状态；概览读取不会执行账期滚动或改写用量。
4. 额度排行保留 `NodeSummary` 的必需字段，以及套餐、用量和相关监控摘要；省略 SSH、配置预览、DNS 绑定等可选字段。
   - OpenAPI 为 `quota_rank` 补充说明；既有 Swift DTO 和额度排行界面可直接读取，无需变更生成器或客户端协议。
   - 删除仅为旧概览分页遍历开放的节点/用户查询字段可见性。
5. 新增 3 项回归测试，覆盖大目录和固定查询次数、批量监控/套餐规则以及空数据库。

## 验证结果

- `cargo test --workspace -q`：175 项通过，包含原有监控历史、重试链、套餐、分页和接口回归。
- 大目录测试使用单连接池，比较 2 个节点与 237 个节点。两次 SQLx 查询日志记录数相同，均为 8 条（6 个业务查询、事务设置和提交；事务管理器的 BEGIN 不在该日志计数中）。计数使用固定全局日志订阅与当前线程的局部计数，避免并行测试的作用域订阅切换影响记录。
- 237 个监控节点完整返回；236 位用户中只装配符合条件的告警。无关节点配置和分配凭据故意设置为不可解密内容，概览仍成功且响应不包含测试秘密标记。
- 额度排行保持最多 5 项，覆盖不同额度下的相同比例、稳定排序和到期重置后的有效用量。概览读取后数据库原始用量保持不变。
- 批量监控验证最新失败采样覆盖旧成功采样、时间相同采样的 ID 选择、探测修订号隔离、活动告警、未关闭缺口、撤权等待/失败及节点告警去重。
- 概览套餐及用量摘要与现有节点套餐读取入口一致；空库保留零数量及未知在线数据的 null 语义。
- `cargo check --workspace --all-targets`：通过。
- `cargo clippy --workspace --all-targets -- -D warnings -A clippy::duplicated_attributes -A clippy::ptr_arg -A clippy::too_many_arguments`：通过，沿用此前记录的既有问题排除项。
- `scripts/verify-overview-client.sh`：DTO、缓存隔离及明暗布局渲染通过；Charts 输出既有自定义锚点提示。
- `scripts/verify-overview-network.sh`：网络、分页刷新、独立失败、缓存、取消及服务切换回归通过。
- `ruby scripts/generate-swift-api-models.rb --check`、`git diff --check`：通过。

## 范围与状态

没有数据库迁移；最新采样查询复用现有节点/时间索引。现有概览响应包含所有节点的监控摘要，因此响应大小和相应内存开销仍随节点数增长。本次减少无关数据装配和查询往返，没有新增概览分页。

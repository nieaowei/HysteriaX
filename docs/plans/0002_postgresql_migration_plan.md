# PostgreSQL 全新初始化迁移计划

## 1. 目标与边界

根据已确认的选择，服务端直接切换为 PostgreSQL，删除 SQLite 支持，采用原生字段类型，保持单实例运行。

- 不导入旧数据库，不提供 SQLite 兼容层、双写或转换工具。
- 新库重新创建节点、用户、订阅和凭据；旧流量、任务、配置版本和审计历史不进入新库。
- HTTP API 路径、JSON 字段、状态码、UTC RFC 3339 时间格式及数字 SSE 游标保持兼容，macOS 客户端无需配合数据库类型变化。
- 本次实现仅修改项目代码、测试、部署配置和文档；不直接操作现有线上数据库或远程节点。

## 2. 数据库与服务端改造

**连接与迁移**

- SQLx 保持 0.8.6，启用 `postgres`，移除 SQLite feature。统一使用 `PgPool`、`PgRow` 和 `Transaction<Postgres>`。
- `DATABASE_URL` 改为必填，只接受 PostgreSQL URL；错误输出不得包含连接密码。连接池默认最大 10 个连接，获取连接超时 5 秒。
- 将当前 14 张表及后续新增字段合并为一份 PostgreSQL 初始 migration，重新建立迁移历史；后续继续使用 SQLx 内嵌迁移。
- 删除 WAL、PRAGMA、SQLite 文件探测、`VACUUM INTO` 和迁移前自动文件快照。数据库升级前备份交由运维脚本执行。

**字段类型**

| 字段类别 | PostgreSQL 类型与 Rust 表示 |
|---|---|
| 业务 ID、外键、密文、哈希 | 保留 `TEXT` / `String`，不同时引入 UUID 类型改造 |
| 布尔字段 | `BOOLEAN` / `bool` |
| 所有业务时间 | `TIMESTAMPTZ` / `DateTime<Utc>` |
| 未加密的 JSON 字段 | `JSONB` / `serde_json::Value` |
| 用量、计数器、版本、大小及尝试次数 | `BIGINT` / `i64` |
| 端口 | `INTEGER` / `i32`，与业务 `u16` 做显式转换 |
| 事件 ID | `BIGINT GENERATED ALWAYS AS IDENTITY` / `i64` |

- 加密后的配置、资源及凭据继续以密文文本保存，不能改成明文 JSONB。
- 保留现有外键、级联规则、唯一约束、取值检查和索引；状态字段继续使用 `TEXT + CHECK`。
- JSON 对象和数组分别添加类型检查；时间比较直接使用时间类型，序列化时统一输出 UTC RFC 3339。
- 原 `COLLATE NOCASE` 查询改为 `ORDER BY lower(name) COLLATE "C", name COLLATE "C", id`，明确采用 PostgreSQL 的大小写折叠及稳定次级排序。

**查询适配**

- 全部占位符改为 `$1…`，替换 SQLite 日期函数和事务语法。
- 同步修改绑定、读取和响应组装，包括 `EXISTS` 布尔结果、`SELECT 1` 整数类型、JSONB 解码及空值处理。
- 保留 revision 条件更新和受影响行数检查；冲突仍返回 HTTP 409。
- 保留模块结构，在数据库模块集中连接、事务入口和公共类型转换，不额外引入 ORM。

## 3. 事务、后台任务与事件一致性

首版优先保持现有写入串行语义，采用**统一写事务入口**：开始事务后立即取得固定键的 `pg_advisory_xact_lock`，持有至提交或回滚。所有应用写入均经过该入口，包括当前独立执行的 INSERT、UPDATE、DELETE。

- 锁只覆盖短数据库事务；SSH、HTTP 请求、下载、休眠和远程部署必须在事务外完成。
- 任务选择、状态转换和事件写入原子提交；保留每节点最多一个运行任务及最多四节点并行执行的行为。
- 流量基线、增量记录、用户累计用量和撤销任务在同一事务内更新；配额重置使用相同写入入口。
- 日志追加、配置版本保存、任务取消和用户凭据变更重新检查事务边界；事务内读取必须通过事务连接执行。
- 事件分配 ID 的事务按顺序提交，避免较大 ID 先提交后，SSE 游标跳过较小 ID。允许序列空洞，不要求 ID 连续。
- 大于 `i64::MAX` 的节点计数器拒绝入账并记录采样失败；累计用量保留现有饱和语义，不允许整数溢出。

为防止意外启动第二个服务端，启动时使用独立 PostgreSQL 连接取得另一个固定键的 session advisory lock，取得后才运行迁移和任务恢复。第二实例直接启动失败；持锁连接每 5 秒检查一次，连接丢失时停止后台任务并结束进程，由部署系统重启。

该方案支持数据库读取并发和远程任务并行，但不以提升数据库写入吞吐为本次验收目标。

## 4. 部署、备份与切换

**部署与开发环境**

- Compose 默认增加 PostgreSQL 18 服务和独立持久化卷，不暴露公网数据库端口；API 等待数据库健康后启动。
- 初始化脚本生成独立数据库管理员密码和应用密码。应用角色拥有业务库及 migration 权限，但不具有超级用户权限；管理角色仅用于初始化、备份恢复及测试库管理。
- 移除 API 的 SQLite 数据挂载、备份挂载和 `HYSTERIAX_MIGRATION_BACKUP_DIR`。保留 Caddy 配置和证书卷。
- 本地开发使用同版本 PostgreSQL，通过 `DATABASE_URL` 连接；服务端不再自动创建本地数据库文件。

**备份恢复**

- 保留备份脚本的 `backup`、`restore <archive>` 命令入口，更新归档格式版本，明确拒绝旧 SQLite 归档。
- 备份停止 API 后执行 `pg_dump -Fc`；归档包含 dump、格式与 schema 版本、校验和及主密钥指纹，不包含主密钥。文件权限为 0600。
- 恢复先验证归档和密钥指纹，再恢复到临时数据库；使用 `pg_restore --exit-on-error`，验证 schema 和约束。
- 停止 API 后替换业务数据库，保留原库；若启动或 readiness 检查失败，恢复原库。失败归档、临时库和原库名称明确输出，便于排查。
- 不增加 PITR、复制或高可用集群。

**已有安装的切换步骤**

1. 使用旧版本完成一次可恢复的备份，保留旧镜像、配置和密钥。
2. 复用现有远程机器时，在旧管理服务仍可用期间通过其卸载流程清理受管安装，确认卸载完成。
3. 停止旧服务，启动全新的 PostgreSQL 和新版服务；不自动删除旧 SQLite 文件。
4. 使用初始化管理员凭据重新连接客户端，重建节点、资源、用户、分配和订阅，再部署节点。
5. 切换后重启客户端，清除旧连接的事件游标，重新刷新管理状态。

文档明确：数据库重置会使旧节点身份、用户凭据和订阅失效；新系统投入使用后，回退旧版本属于另一轮维护操作，不是无损回滚。

## 5. 测试与验收

- Rust 数据库测试全部运行于真实 PostgreSQL，各测试使用独立临时数据库；CI 提供 PostgreSQL 18，数据库不可用时测试失败，不能静默跳过。
- 更新所有依赖 SQLite 的测试及验证脚本；用 PostgreSQL 故障注入替代 SQLite trigger 测试。
- 覆盖全新建库、重复启动、迁移校验失败、第二实例拒绝启动和持锁连接中断。
- 验证同 revision 并发编辑仅一次成功；事务失败后业务状态、日志和事件均回滚。
- 验证并发任务领取无重复、同节点任务串行、重启恢复及失败重试。
- 验证重复采样不重复收费、跨节点累计、采样与配额重置交错、计数器溢出及配额撤销。
- 人为延迟事件事务，验证 SSE 续读不漏事件；覆盖超过 100 条事件的分页续读和序列空洞。
- 验证布尔、时间、JSONB、可空字段、非 ASCII 名称排序及原 API 响应结构。
- 完成备份恢复演练，包括密钥不匹配、损坏归档、恢复失败及原库回退。
- 运行 fmt、check、test、clippy、现有鉴权/订阅/采样/重启验证，以及 amd64、arm64 部署矩阵；保留真实 Hysteria/Mihomo 的部署、转发和撤销验证。
- 更新安装、架构、备份、排障和验证文档。历史 SQLite 验证记录标明对应旧版本，不作为 PostgreSQL 验收证据。

完成标准：全新 PostgreSQL 部署通过完整服务端回归，客户端通过现有 API 完成管理流程，备份可恢复，运行代码与测试不再依赖 SQLite。预计约 **7–12 人日**，不含线上节点重新配置和实际切换时间。

# 0031 后台汇总和列表查询优化

状态：已实施并部署（2026-10-15）。诊断背景见 docs/diagnostics/20261015_full_scan_audit.md。

## 实施

1. 后台小时/在线分钟重建由待处理键驱动 LATERAL 范围查询，OFFSET 0 防止展开为大表扫描。删除旧汇总时先按主键找到目标 ctid，再以 Tid Scan 删除；未处理队列为空时不读源数据。
2. 迁移 0025 安装 PostgreSQL 的受信任 pg_trgm 扩展，创建任务与审计文本搜索的 GIN 索引。text-only 的不可变拼接函数保持原 concat_ws 跳过 NULL 的语义；LIKE 参数转义反斜杠、百分号、下划线，保留字面子串搜索。分页事务使用 force_custom_plan，避免不同参数退化成统一计划。
3. 任务按节点、类型、阶段、状态，审计按动作、对象类型/ID、操作者，增加匹配稳定 ID 次序的复合排序索引。
4. audit_totals 在迁移时回填。INSERT/DELETE 语句触发器只统计本次变化的 transition table，TRUNCATE 清零，更新与回滚保持一致。无搜索时直接读取总数，有条件搜索仍精确计数匹配记录。
5. 迁移 0026 增加无密钥的 credential_directory 轻量目录头部视图，覆盖托管凭据、管理员令牌、订阅凭据及用户节点凭据。数据库执行分类、筛选、排序、分页，只加载选中页的完整摘要、引用及实时状态。移除全量静态目录加载后在 Rust 筛选/排序/切片的路径。引用查询约束到本页托管凭据 ID，继续使用权威引用索引；密钥和凭据 payload 不进入列表。
6. 保留精确 P50/P95 与已有接口、排序方向和响应结构。API 仍是 /api/v1。

## 剩余成本与边界

- 精确 P50/P95 仍读取所选窗口的成功探测样本；本次没有改变统计精度。
- 一两个字符或高命中率的子串，优化器仍可能合理选择扫描；不能承诺所有自由文本都走索引。
- 凭据的精确总数、跨来源合并及实时状态排序仍需要处理匹配的目录头部；已消除全量完整摘要和引用在应用层构建的成本，不宣称所有目录查询都只读一页头部。
- 小表的顺序扫描不应强制替换为索引。新增索引会增加相关字段写入时的维护成本。
- 冷页面读取造成的首次延迟波动仍可能存在。

回滚脚本：scripts/rollback-query-optimization.sql。须先停 API，再回滚新增视图、函数、索引、派生计数及迁移记录至 0024，然后恢复备份 .env 并使用旧镜像启动。脚本拒绝在存在高于 0026 的迁移时运行；保留源数据及 public.pg_trgm 扩展。完整验证数据见 0031_query_optimization_deployment_verification.json。

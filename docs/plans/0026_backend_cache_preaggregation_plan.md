# 0026 后端缓存与预聚合实施记录

日期：2026-10-14

## 目标与协议调整

落实全后端缓存/预聚合审查，减少重复解密、重复目录装配、原始历史扫描和独立 SSE 轮询。用户允许破坏性变更，无需兼容旧客户端。

管理 API 保持原有 `/api/v1` 路径及 `1.0.0` 版本，直接调整原接口响应和行为，不新增 v2 入口或旧客户端兼容层。macOS、OpenAPI、生成模型与验收脚本同步更新。节点列表只返回摘要，配置和脱敏 YAML 从详情读取；保留原路径分页与过滤，不新增 `/page` 或全量模式。

## 实施步骤（已完成）

1. **有界缓存及提交后失效**
   - `cache.rs` 实现 TTL、容量/字节限制、同键请求合并、取消恢复、错误不缓存及超大响应旁路。
   - 响应缓存最多 256 项/32 MiB，单项最多 2 MiB；目录计算缓存 32 项/16 MiB；脱敏预览 256 项/16 MiB。缓存均在进程内，不引入 Redis。
   - 管理 GET 按管理员 ID、规范化查询与数据库 generation 分区。概览 3 秒，历史 60 秒，任务/发布批次 1 秒，其他可缓存 GET 5 秒。
   - 0016 迁移为源表建立事务内 generation 触发器，覆盖 API、采集 worker 和直接 SQL；回滚不发布新版本。配置 generation 单独排除采样用量与使用时间更新。
   - `Cache-Control: no-cache` 强制重算；`no-store` 旁路响应缓存。管理响应和订阅的 HTTP 策略为 private/no-store。新增鉴权保护的 `/api/v1/cache` 统计入口，不暴露缓存键或内容。

2. **鉴权与批量查询**
   - 每次管理鉴权按 Token 哈希唯一索引读取，使用时间写入限频为 60 秒；不缓存鉴权放行结果。
   - 节点列表批量读取监控、套餐、告警与 DNS 绑定。配置预览按配置依赖版本缓存脱敏结果。
   - 用户列表批量读取分配、权限来源与组成员关系；授权组列表统一快照批量装配；DNS 绑定批量读取记录；凭据详情批量读取发布批次及项。
   - 资源只查询配置实际引用的 ID；凭据版本在一次配置解析中去重批量读取并临时解密。TLS 证书/密钥匹配校验只缓存内容摘要对应的成功标记，不持久缓存通用明文凭据。

3. **凭据引用索引（0017）**
   - 源配置变动进入 `credential_reference_dirty`，派生边表覆盖目标、部署与历史配置的引用位置。
   - 启动回填；引用读取和删除/归档校验在现有串行写事务内同步排空待更新项。直接 SSH、分配、DNS 与活动批次关系继续直接查询。
   - 目录不再为每页解密全部配置，通过索引读取引用计数；同 generation 共享无秘密目录快照后筛选分页。

4. **统计读模型（0018、0019）**
   - `traffic_minute_totals`：用户流量/网卡流量按节点、UTC 分钟聚合增量及不完整样本计数。
   - `user_node_usage`：用户/节点历史累计收发及最后采样。与当前账期计费用量分开，不改现有计费状态和鉴权依据。
   - 流量 INSERT/UPDATE/DELETE 同事务维护派生表，迁移回填历史；NUMERIC 累计避免派生总量溢出使计费写入失败。
   - `online_cycle_metrics`：每个采样周期的全局跨节点去重用户、连接和覆盖质量，以及单节点维度。变更周期去重入队，后台每 10 秒重建；历史读取先同步处理待更新周期，在一致快照内查询。
   - `probe_minute_totals`：探测次数与成功数。精确 P50/P95 继续从原始成功延迟计算，不平均百分位数。
   - 每个展示桶采用完整分钟聚合加原始边缘样本，保持滚动窗口、迟到、缺口、节点过滤和夏令时语义。
   - 历史新增 `metrics=traffic|quality|all`，客户端按页请求所需指标。公开历史 `generated_at` 向下对齐 UTC 分钟，最多落后当前时刻 60 秒；窗口以该时间为结束点。在线与探测原始保留期增至 31 天。

5. **订阅、SSE 与固定安装资源**
   - 订阅每次重新验证 Token、用户状态/到期/额度与节点资格。只有生成内容按用户、配置 generation、格式、客户端能力及当前合格节点集合缓存 5 秒。
   - 每进程一个共享事件读取器，1 秒轮询；内存环最多 4096 项/4 MiB。缓冲范围外从数据库按游标回放，支持 job_id 过滤；数据库仍为持久事件真源。
   - 安装包按固定资产及 SHA-256 缓存，校验后原子落盘，同键合并下载；磁盘预算 300 MiB。可配置 `HYSTERIAX_ASSET_CACHE_DIR`，清理陈旧临时文件，损坏缓存重新下载。
   - 安装包与 DNS 提供商复用 HTTP 客户端连接；外部写入和冲突确认继续读取新鲜状态。

6. **客户端刷新**
   - `/version` 提供 `directory_generation`。定时/SSE 刷新仅在配置版本变化时遍历目录；监控、概览及活动列表/详情独立刷新。
   - 手动刷新及写入后的刷新重新读取目录；显式历史刷新发送 no-cache。历史缓存键区分指标集合。
   - 更新概览渲染夹具，使流量和质量缓存分别命中。

## 运行与后续观察

源 generation 采用粗粒度失效：安全优先，但持续采样可能降低长 TTL 的命中率。通过 `/cache` 观察命中/合并/容量；本次未以生产压测证明延迟收益，不宣称固定性能倍数。

任意关键词 COUNT、深页 OFFSET 仍由数据库执行；未基于假设引入搜索预聚合或任务计数派生表。健康检查、计费、租约、写入权限/冲突校验及外部执行确认不进入普通响应缓存。概览仍返回全部节点监控摘要，响应大小随节点数增长。

大数据库升级需要回填统计及配置引用，启动迁移时间取决于历史规模；升级前保留数据库备份。该版本需要配套更新服务端和客户端。已实施并于 2026-10-14 部署至 https://hysteriax.cc，源代码改动尚未提交。镜像在本地构建后上传服务器，继续使用 `/api/v1`。

## 历史趋势首次查询优化（2026-10-14）

- 线上只读执行计划发现：原始边缘分支先扫描完整展示桶，再过滤掉整分钟记录；聚合表结束条件对索引列进行时间运算，导致各桶重复扫描后续分钟。
- 改为预先计算完整分钟的起止范围，直接使用索引列上下界；只为非对齐边缘生成原始采样区间。分钟对齐窗口中原始明细分支不执行，非对齐窗口保留精确结果。
- 通用预备计划可能高估扫描量并触发 JIT 编译。趋势只读事务使用 `force_custom_plan`，并关闭 JIT，避免新连接首次编译开销；设置随事务结束恢复，不修改数据库全局配置。
- 新增执行计划回归测试，验证对齐窗口不扫描原始流量，非对齐窗口仍补算边缘。187 项全量测试和严格 Clippy 通过；在线用户/网卡、24h/7d/30d、对齐/非对齐的 12 组双向差集均为零。
- 本次不改变数据库结构、API 路径或客户端契约；修复继续在本地构建镜像并上传部署。线上 SQL 与无响应缓存的接口测量见 [首次查询优化验证](0026_history_index_ranges_verification.json)。
- 最终镜像 `history-index-ranges-20261014-v3` 已部署且 healthy，API 仍为 `/api/v1`，数据库仍为 0019。新进程首轮、强制绕过缓存的用户流量请求：24h 4275→375 ms，7d 5098→76 ms，30d 2721→91 ms；网卡首轮为 75/57/103 ms。三轮共 18 次请求全部成功。数字是同服务器实测，包含后台负载，不代表固定延迟保证。

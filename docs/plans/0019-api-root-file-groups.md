# 0019 API 根目录文件归组

实施日期：2026-11-05（Asia/Shanghai）。按用户后续要求，API 边界允许建立一级分组目录，继续保持内部辅助模块扁平。

## 范围

仅移动文件及调整明确的模块路径绑定，不修改业务函数、接口、数据库、条件编译和测试名称。设计前提仍为 10 万用户、1 万节点，无数据迁移或部署。

## 已实施

1. 将 21 个直接散放在 `api/` 的文件归组。根目录仅保留 `mod.rs` 与独立的 `client_summary.rs`，不为单独的摘要文件新建目录。
2. 管理员令牌实现及其测试使用 `admin_tokens/mod.rs`、`admin_tokens/tests.rs`；令牌使用记录及测试也归入 `admin_tokens/`。SSH 指纹实现与夹具归入已有 `nodes/`。
3. 事件流、执行复核、幂等分别使用 `event_stream/`、`execution_rechecks/`、`idempotency/` 一级目录，配套测试与实现同组。
4. 跨模块的审计/任务分页、认证争用、响应缓存、管理契约、事务、查询计划与路由测试，以及共享夹具集中到 `api/tests/`。没有新增测试包装模块，通过 `#[path]` 保持原 Rust 模块层级、私有访问关系和测试过滤器。
5. 新位置可由常规模块规则解析时去掉旧的显式路径，否则同步绑定实际文件位置。业务模块的命名空间、可见性和调用路径不变。更新数据库表用途文档的源码链接及架构文件组织约定。

# 0039 — 流量计费批量检查节点分配，部署生产

## 问题与修复

生产流量采样批次包含数百条已不再分配的用户计数，计费每页最多 500 条记录逐项执行 EXISTS，造成大量数据库往返和长时间持锁。

1. 将分配关系改为每页一次批量查询，在内存集合中判断；保留节点、批次、排序用户的锁顺序、计费、基线、账本和检查点行为，每页重新检查分配。
2. 新增 504 条计数跨页回归，覆盖已取消分配、其他节点分配、未知用户、页间取消分配和完成后重试；流量模块 40 项测试通过，格式和 diff 检查通过。
3. 与上一版构建指纹比较，服务端仅 traffic/batches.rs 与 traffic/batch_tests.rs 改变；数据库 schema、官方 SQLx 依赖及连接归还清理保持一致。
4. 本地构建 linux/amd64 镜像 `hysteriax-server:traffic-batch-20261026-r3`，本地构建阶段执行模板运行时检查，归档传输生产；激活前验证归档、文件层、运行配置和服务端二进制。
5. 备份配置并仅重建 API，验证内外网 readyz、管理接口、后台批次推进和数据库状态；将生产 Compose、api.env、redis.env、Caddy 配置保存本地。

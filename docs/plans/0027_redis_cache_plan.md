# 0027 Redis 缓存实施记录

日期：2026-10-14

## 实施范围

管理响应、目录计算快照、脱敏配置预览及订阅生成结果改用 Redis 作为主缓存。保留 `/api/v1`、数据库聚合表及事务内失效版本号。安装包继续使用磁盘缓存；SSE 环、主机采样和证书校验等短小进程状态继续保留在内存。

## 已实现

1. 增加 redis-rs 异步连接管理器和 `HYSTERIAX_REDIS_URL` 配置。Docker Compose 添加独立 Redis 8 服务、随机认证密码、64 MiB 上限、allkeys-lru 淘汰、AOF 持久卷及健康检查，不发布宿主端口。
2. Redis 键按数据库连接配置摘要、缓存类型及原有身份/数据版本/查询键摘要隔离。内容使用现有主密钥认证加密；响应编码保持状态码、重复/二进制头及任意响应字节。
3. 保留原有 TTL、强制刷新、超大内容旁路及错误不缓存规则。有效 Redis 返回不保留本地完成值，内存只负责同进程请求合并；数据库提交后的 generation 变化使旧键失效，旧内容由 TTL/容量策略淘汰。
4. Redis 操作整体最多等待 150 ms；故障打开两秒熔断，查询回源数据库，并使用最多两秒的有界内存缓存。Redis 恢复后自动重新使用主缓存。鉴权和业务资格检查继续读取当前数据库状态。
5. `/api/v1/cache` 增加后端类型、Redis 配置/熔断状态及错误计数，不返回连接 URL、密钥、缓存键或内容。新安装初始化脚本生成 Redis 密码，已有实例在受保护 `.env` 中补齐。
6. 数据库恢复和恢复失败回退时，在重新启动 API 前清空专用 Redis 缓存，避免数据库版本号回退后与已有键碰撞。恢复脚本已同步服务器。

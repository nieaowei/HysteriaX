# 0006 固定 Schema 构建期自检与运行时内存修复

状态：已完成。日期：2026-10-19。

## 问题与目标

jsonschema 0.33.0 的全局元 Schema 校验器在自检固定目录时缓存大量递归资源副本和完整路径。Server1 约 1 GiB 内存出现严重换页、数据库连接池超时和 readyz 间歇失败。将固定规则自身的自检移到独立构建进程，保留用户配置的全部校验逻辑。

## 实施

1. 固定并保留 jsonschema 0.33.0，使用可审查的最小依赖补丁公开已有的跳过元自检选项，不改变默认行为或实例校验。
2. 构建脚本检查原始与实际变换后的两份固定 Schema，生成 OUT_DIR 内嵌规则。运行时只能编译这些已检查产物，不接受外部 Schema。
3. 为原始和变换后的 Schema 构建失败建立隔离回归；使用独立进程检查首次、重复和并发校验的行为及 Linux RSS。
4. 运行语义、订阅生成、格式和静态检查；按项目要求本地构建 amd64 镜像，验证后传送并部署测试服务，保留回退镜像及配置。

## 验收边界

- 损坏任一原始或准备后的规则必须阻止构建；CI、普通 Cargo 构建和容器镜像构建均经过同一个门禁。
- 用户配置的错误类型、未知扩展、跨联合分支字段、引用、平台限制、发布和实际节点输出继续通过既有回归。
- 新进程执行两个格式的五平台验证、试生成、16 次重复和 4 线程校验；Linux 峰值 RSS 不超过 96 MiB，重复后 RSS 增量不超过 16 MiB，Swap 为 0。
- 不在本计划内改动发布写事务或数据库参数；这次改动只处理固定规则自检的运行时内存开销。

本地通过 Buildx 构建 `linux/amd64` 镜像 `hysteriax-server:0006-schema-memory-20261019`，经 `docker save`/SSH/`docker load` 传送后部署到 Server1。没有数据库迁移或节点配置变更。旧镜像保留为 `hysteriax-server:pre-0006-20261019`；服务器配置快照为 `/home/nieaowei/HysteriaX/backups/schema-memory-0006-20261019/previous.env` 和同目录的 `compose.yaml`。

部署后容器 healthy、无自动重启。两种格式加载、反复实际预览及错误配置检查后，API PSS 约 57.7 MiB、SwapPss 为 0；readyz 连续 HTTP 200。服务器本机经公网域名测得约 0.014–0.074 秒，开发机公网复测约 1.43 秒，不能混为同一网络口径。此前约 1 GiB 主机上的数据库与其他进程仍有自身资源消耗，本次修复不等于承诺所有未来负载下都不会超时。

构建脚本会生成并嵌入通过自检的确切规则产物，普通 Cargo 构建、CI 和 Docker 构建共享该入口。运行时没有接收或编译外部 Schema 的接口；新增离线 `--check-template-runtime` 仅用于无数据库、无密钥的生产路径验证。

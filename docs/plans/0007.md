# 0007：精简 Rust 测试中的过渡期验证

日期：2026-10-28。

## 目标与范围

按用户“清理”的要求，实施测试审计中的 Rust 精简项，以及用户补充要求删除的两份过时 Python 迁移验证脚本。保留计费、授权、凭据轮换、事务回滚、租约及故障恢复的业务断言，移除旧架构切换遗留的测试负担。此次不扩展到 macOS 测试整理。

## 实施计划与完成情况

1. 删除两个数据库旧锁夹具自测，以及一个 DNS fixture 旧锁自测，共删除 3 个测试。它们验证测试工具或 fixture 准备过程，不验证生产业务路径。
2. 删除 45 个文件中的 47 处旧触发器禁用 SQL。当前基线不再创建 `hysteriax_serialize_writes`；同时删除变空的 helper、调用与导入。混合 SQL 语句中的正常 fixture 数据、并发同步和故障注入保留。
3. 删除 50 组分散的旧锁持有/释放代码。凭据读快照测试仍需要未提交事务，改用普通 `pool.begin()`；保留业务并发、回滚、幂等与结果断言，调整已经不再描述实际行为的测试名称。
4. 旧锁调用收敛为 4 处：`db/cutover_tests.rs` 集中验证 `write` / `serializable`，以及认证读取、作业 claim/release、配置 worker handoff 三个代表性入口。保留夹具供这些回归使用，不再测试夹具自身的锁调度行为。
5. 将 3 个重型执行计划检查标记为显式忽略，保留原有断言；新增 `scripts/verify-query-plans.sh` 串行、精确选择这三项。常规套件不运行这些性能检查，专项也不会误运行 SSH 或真实快照测试。
6. 更新 `docs/deployment-testing.md` 与审计状态，保存本编号实施记录。原有未跟踪计划 0001～0005 保留。
7. 删除 `scripts/verify-credentials-migration.py` 和 `scripts/verify-tls-pairs-migration.py`，共 245 行。受测历史升级链已移除，确认工作流、运行脚本和业务代码没有引用，旧迁移数据库 URL 变量也没有残留使用；更新审计中的完成状态。

Rust 修改覆盖 61 个文件，净减少 401 行；server 测试声明由 1,073 减至 1,070，默认忽略项由 11 增至 14。其中新增的 3 个忽略项通过独立入口实际执行，不以忽略代替验证。

## 验证环境

创建自有临时 PostgreSQL 18 容器，使用独立空数据库与测试 schema。没有读取仓库 `.env` 或复用现有数据库。Rust 测试使用 `RUST_MIN_STACK=16777216`，全量运行使用 4 个测试线程。

- `cargo check --workspace --all-targets` 通过。
- `cargo fmt --all -- --check`、`git diff --check` 和性能脚本 `bash -n` 通过。
- 全量 `cargo test --workspace -- --test-threads=4` 完成：server **1055 通过、1 失败、14 忽略**，耗时 428.89 秒。不能记作全量通过。
- 唯一失败项为 `credentials::rotations::metadata::tests::a_new_activation_generation_invalidates_prepared_results_even_with_the_same_active_id`；失败发生在公共 `metadata_fixture_with_pool` 内，发布版本断言实际为 1、预期为 2，尚未进入该测试主体。该断言及之前的生产调用未被本次清理修改。单独串行复跑该测试通过。
- 随后串行运行整个 `credentials::rotations::metadata::tests::` 测试组：**13 通过、0 失败**。
- `bash scripts/verify-query-plans.sh` 实际运行三项，各 **1 通过、0 失败**，分别约 2.04、0.76、1.34 秒。
- `cargo test -p hysteriax-template-validator`：**1 通过**，doc-tests 无测试。

- 静态复核确认：旧触发器名在 Rust 源码中不再出现；旧锁夹具只剩 4 个调用；原混合 SQL 中旧 DO 块之后的内容均保留；仅删除上述 3 个测试函数。

不将一次失败后的单独通过等同于全量全绿，也不据此次运行推断精简后的性能提升比例。

# 授权组窗口缩放性能优化

日期：2026-10-08

## 问题与实施

授权组操作栏的 ViewThatFits 同时维护完整、紧凑两个候选方案；更大的问题是详情内容在 GeometryReader 的闭包内构造，窗口每次改变尺寸都会重新生成成员数据并排序。大量成员时，缩放因此与总成员数耦合。

1. 移除授权组页的 ViewThatFits，保持单一操作栏：管理用户按钮及更多操作菜单。编辑名称、管理节点、删除组仍在菜单内。
2. 将列表和选中组详情在几何闭包外构造，使缩放只调整两栏的尺寸，成员内容不随每个像素重复生成。
3. 表格列宽按 32 点区间更新，保持整个视口实时铺满，并将列宽预算向下取整，避免窄窗口出现横向滚动条。
4. 在现有缩放测试中增加 6 位及 5,000 位成员两个授权组场景。

## 性能结果

同一机器、同一程序，以 48 个窗口尺寸变化采样；每次完成 AppKit 布局后记录耗时。以下是布局耗时，不等同于真实屏幕 FPS。

| 场景 | 优化前平均 | 优化后平均 | 优化前 P95 | 优化后 P95 |
| --- | ---: | ---: | ---: | ---: |
| 6 位成员 | 8.74 ms | 6.56 ms | 12.30 ms | 12.41 ms |
| 5,000 位成员 | 264.81 ms | 9.07 ms | 305.31 ms | 18.19 ms |

少量成员的 P95 未改善；大量成员的布局成本明显下降。不能将结果全部归因于 ViewThatFits，数据子树稳定化是关键改动。

命令：`scripts/verify-main-split-resize.sh <输出文件> groups_6 groups_5000`。

原始结果保存于 `0017_authorization_group_resize_before.json` 和 `0017_authorization_group_resize_after.json`。

## 功能验证

保持最小窗口填充、左侧列表背景、成员选择、跨页批量操作、权限预览与证书校验。两项隔离界面回归均通过：`apps/macos/.build/authorization-ui-1791393798.xcresult`。覆盖最小窗口边界、长 UUID 无横向滚动、跨页选择、添加/移除/取消、权限预览、mTLS 阻止提交与创建组保存。

最终 Xcode 构建及 `./script/build_and_run.sh --verify` 启动验证通过。

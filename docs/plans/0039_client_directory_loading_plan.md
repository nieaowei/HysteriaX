# 0039 客户端首屏加载与通知摘要

日期：2026-10-16。

## 实施

- 连接、手动刷新及配置代次变化只加载凭据、节点、用户各首屏 50 条，不再自动遍历目录。
- 仍使用完整集合的批量选择、成员编辑、历史节点筛选控件，仅在打开对应界面时准备所需目录。同类请求合并，已准备目录按配置代次失效，保留批量操作完整性。此路径仍需按目录大小读取全部分页，后续可单独改造为远程搜索选择器。
- 当前任务和用户分配详情按关联节点 ID 补读，避免首屏外节点的重试/指纹确认操作消失。
- 增加鉴权的 `/api/v1/client/summary` 与能力标识，使用数据库全局聚合返回用户统计，并只读取有提醒的节点、临近到期的托管凭据；全局统计及通知与列表页解耦。
- 旧服务没有 client_summary 能力时保留原有完整加载行为，避免统计漏计；先升级服务端再使用首屏优化。
- 显示快照中的目录各最多保留 50 条；缓存完整统计与提醒。OpenAPI 同步生成类型和操作绑定。

## 验证

- 超过 200 条数据的服务端集成测试验证全局计数、首屏之外的额度和凭据提醒、归档过滤、鉴权及无秘密回显。
- 客户端网络测试验证首屏 50 条、普通/手动刷新不读取 200 条目录页、显式选择目录读取合并与完整性、磁盘快照上限。
- 运行 Rust 全量测试、Clippy、格式和生成契约一致性检查；macOS 客户端构建及启动验证。

验证结果：211 项 Rust 测试通过；新增摘要的非法过期时间回退测试通过；客户端网络、授权组和 SSH 指纹测试通过；macOS 构建和启动验证通过。

## 已实施

1. 将 49 个内嵌测试模块（原文件约 9,290 行）拆到所属模块目录，包括部署、任务、配置、节点、套餐、探测、缓存、凭据、DNS、执行、SSH 和流量等模块。保留原测试模块名、函数、断言和条件编译。入口的关闭测试单独存放在 `src/shutdown_tests.rs`。
2. 将 26 个散落的测试与夹具文件归入所属目录。例如 `ssh_execution_tests.rs` → `ssh/execution_tests.rs`，`overview_tests.rs` → `overview/integration_tests.rs`，`api/nodes_test_support.rs` → `api/nodes/test_support.rs`。属于 jobs 的节点清理、指纹确认测试放在 `jobs/`，保留原模块归属。
3. 移除 36 处可由 Rust 标准目录规则替代的 `#[path = ...]`，保留对应 `#[cfg(test)]` 和模块声明。同步调整测试内读取 SQL 和夹具的相对路径，引用的文件保持一致；快照节点清理验证脚本的源码摘要路径也同步指向新文件，测试过滤器不变。
4. 在 `docs/architecture.md` 补充文件组织约定：有子模块或测试的模块统一以目录中的 `mod.rs` 作为入口，实现、测试和测试辅助文件放在一起；已有命名测试套件保留模块名，保持脚本过滤器有效。

5. 按用户后续意见，将 107 个与同名目录并存的模块入口移入对应目录，统一使用 `mod.rs`，包括嵌套业务模块和测试汇总模块；不新建额外目录。调整 17 处相对资源引用路径，所读取资源保持一致。同步更新数据库表用途文档中的源码链接、快照清理和 ACME 验证脚本的源码路径。锁争用对比脚本根据被归档版本的实际文件布局选择模块入口，兼容原有单文件基线及目录入口。

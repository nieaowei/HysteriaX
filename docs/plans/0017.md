# 授权组节点增删持续延迟排查

日期：2026-10-29（Asia/Shanghai）
状态：已修复、无备份部署并验证

## 问题与证据

1. 用户报告上次发布后，增删授权组节点依然缓慢。运行的 macOS 应用已于上次发布后重新构建，不能直接归因于旧客户端。
2. 在生产创建无成员临时组，依次添加和移除一个现有节点，无用户授权变化：创建 7.513 秒，添加节点 16.421 秒，移除节点 11.928 秒，删除 5.922 秒。临时组已删除。
3. 近 30 分钟日志中，节点行锁检查与资源租约更新有大量秒级慢查询。数据库瞬时活动快照主要为 ClientRead，也有 transactionid 等待；快照不能证明整段请求没有锁竞争。API CPU 瞬时约 8%，内存约 60 MiB。现有生产规模 6 用户、4 节点。
4. 服务端提交前分两轮快照重复读取组、成员和授权图；每次读取组又需要三条 SQL。授权事务对相关节点持有 NO KEY UPDATE 锁，与后台监控的同类锁互斥，延长等待和持锁时间。

## 实施

1. 证书授权计划和连接密码候选在同一只读快照准备，去掉生产路径的第二轮组/成员/授权图读取；重试仍复用已生成的材料，正式提交仍重新校验版本、计划和授权图。
2. 单组详情改为一条 SQL，相关成员与节点使用带索引过滤的排序数组子查询，避免多次往返且不产生成员与节点的笛卡尔积。
3. 授权路径对节点使用 KEY SHARE 防止并发删除，允许非关键字段更新；用户、组和证书锁保持，撤权任务自身所需的节点锁保持。无成员且无证书计划时跳过空用户/证书锁查询。
4. 记录授权组提交的准备、事务及总耗时，不记录密码、令牌或请求正文，便于区分后续慢请求阶段。
5. 增加并发回归：后台持有节点 NO KEY UPDATE 锁时仍能完成节点授权；KEY SHARE 仍阻止节点删除；节点移除继续生成撤权任务。

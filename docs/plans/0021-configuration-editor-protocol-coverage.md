# 0021 配置编辑器的协议与通用选项覆盖

## 目标与版本

继续落实配置文档中的编辑交互，避免只优化 HTTP Client。以项目的 sing-box 1.14.2 Schema 和同标签文档为基线。滚动网站已经包含 1.15 功能，不能据此把当前内核尚未支持的字段加入受验证表单。

## 已实施

1. 从上游 v1.14.2 文档提取 111 个页面、1159 个不重复的页内字段标题，生成 `TemplateDocumentationOrder`。只提取字段顺序，不把示例配置当作默认值。生成脚本随仓库保存。
2. 普通协议、共享对象、嵌套 OpenVPN/OpenConnect 配置及根表单使用文档顺序；保留用户指定的拨号字段顺序、必填星号和 DNS 缓存首项开关。
3. TUN 拆分接口、DNS、路由接管、自动重定向、流量范围、UDP NAT 和系统代理。`auto_route`、`auto_redirect`、`dns_mode` 联动相应控制项。
4. Tailscale 拆分登录、节点身份、子网与出口、中继、系统接口、状态目录及 SSH；系统接口、出口节点和中继配置控制其关联字段显示。
5. OpenVPN 拆分接口、远端、认证、密钥、数据通道、保活与重协商、路由推送；禁用 MSS、ping restart、定时重协商时隐藏对应参数。OpenConnect 拆分认证、客户端身份、主机检查与会话参数。
6. 证书提供者拆分签发、账户、域名验证和存储；ACME 的 HTTP / TLS-ALPN 禁用开关及 DNS01 验证决定哪些端口与挑战选项可编辑。
7. 多路复用、UDP over TCP、ECH、uTLS、Reality、Brutal 等小型对象直接在当前编辑区展开，保留开关对子字段的控制。大型对象和集合继续采用概览与宽编辑面板。
8. HTTP Client 的拨号设置和 TLS 条件字段共用通用显示规则。所有接收窗口输入统一支持容量字符串、整数和 UInt64，不再额外选择类型。
9. 修正监听 `detour` 被误当作出站拨号 `detour` 的问题：不再错误隐藏其余监听选项，帮助文本及文档链接指向监听语义。
10. 规则动作参数根据当前动作的 Schema 分类，避免 `override_port` 等被误分到匹配条件。

## 数据约束

- 浏览表单和预览默认值不写入文档。
- 隐藏子字段保留原值，开关操作支持撤销和重做。
- 不修改上游 Schema、内核版本、服务端验证或全局空字段处理策略。
- 未知字段继续保留并通过源码编辑；字段顺序覆盖不代表所有上游运行时行为都已做专用编辑器。

## 验证

- 客户端模型检查：遍历协议变体，确认排序无丢字段；验证 TUN、Tailscale、OpenVPN、ACME、规则动作、监听 detour 的行为与虚拟默认值。
- 真实 SwiftUI 离屏检查：条件行增减、保留隐藏值、撤销与重做；共享接收窗口的字符串、整数与 UInt64 切换；原有 Picker、复杂集合、HTTP Client 回归。
- Xcode Debug 构建；不重启用户正在使用的应用。

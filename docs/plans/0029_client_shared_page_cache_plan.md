# 0029 客户端共享分页缓存

状态：已实施（2026-10-14）。

## 问题和目标

分页列表只在 SwiftUI 页面局部状态中保存响应，导航离开再回来会再次请求，连接状态下也不会使用原来的离线目录快照填充列表。保留服务端分页，在共享 ManagementStore 中缓存已访问的查询结果，恢复切换页面先显示已有数据的体验。

## 实施

1. 新增 ListPageCache，缓存跨页面存活的列表摘要。缓存键包含连接会话、服务地址、语言、响应类型、页码、每页数量、筛选和排序；字段采用 JSON 数组编码，避免搜索文本中的分隔符产生冲突。
2. 接入节点、用户、凭据、任务、审计和 DNS 记录分页。页面同步读取共享缓存显示，再异步检查新鲜度；每次进入页面（包括切换页码、筛选或排序）都立即请求服务端，已有缓存先同步显示；即使缓存未过期也重新验证，已有缓存的验证请求发送 no-cache。错误不删除旧缓存。
3. 节点、用户、任务缓存 15 秒；凭据、审计、DNS 记录缓存 60 秒。保留现有自动刷新触发作为过期检查；页面持续显示期间，无关概览刷新不会使新鲜列表失效；15/60 秒有效期仅用于此类自动刷新判断，不限制重新进入页面的更新。SSE 任务事件使节点、用户、任务页失效；目录版本变化使所有列表失效。凭据运行状态等变化未收到专属事件时，以 60 秒缓存周期更新。
4. 手动刷新和现有写操作完成后的 refresh() 使缓存失效；已有缓存的重新请求发送 no-cache 绕过服务端响应缓存。DNS 目录刷新使 DNS 分页失效，页面进入时目录未过期则复用，不重复遍历目录。
5. 同一查询的并发读取合并为一次请求。页面消费者取消不会破坏其他消费者的请求；连接变更清空缓存并更新会话标识，旧请求无法回填新连接。
6. 缓存仅存程序内存，不增加持久化分页副本，不缓存凭据详情或密钥。上限 48 个查询、16 MiB 总响应数据，单响应超过 2 MiB 不缓存；按最近访问时间淘汰。原有 UserDefaults 目录和历史快照保留。

## 验证

- scripts/verify-list-page-cache.sh：复用、过期、错误保留、按类型失效、绕过服务端缓存、并发合并、取消、连接隔离、数量和大小上限。
- scripts/verify-overview-network.sh：真实 APIClient/ManagementStore 模拟传输检查，共享分页显示、重新进入立即验证、概览刷新不重复请求、手动刷新发送 no-cache、服务切换隔离，以及原有概览和分页契约。
- scripts/verify-dns-client.sh：DNS 客户端回归检查。
- script/build_and_run.sh --verify：Xcode Debug 构建并启动项目客户端。

此次只修改客户端缓存行为，无数据库迁移、后端接口或容器变更。

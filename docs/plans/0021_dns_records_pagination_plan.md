# 0021 DNS 记录页服务端分页

日期：2026-10-09

## 目标

为 DNS 记录页增加分页和总数显示；连接、域名区域、搜索及名称/目标排序覆盖所有可见记录。保留记录详情、编辑、节点绑定和跨页跳转流程。

## 实施步骤（已完成）

1. 新增 `GET /api/v1/dns/records/page`，返回 `{ items, total, page, page_size }`。
   - 默认第 1 页、每页 50 条，支持 1–200 条；非法参数返回 400，越界页码返回最后一页，空结果返回第 1 页。
   - 连接与域名筛选组合应用；搜索覆盖名称、目标和记录 ID，按字面子串忽略大小写匹配。
   - 名称/目标排序采用白名单，名称、类型和 ID 为稳定排序的后续字段。
   - 可见性沿用完整目录：未删除记录可见；已删除但仍被 DNS 绑定引用的记录保持可见。
   - 总数和页数据在同一个只读、可重复读事务中读取，保留完整记录字段及绑定节点信息。
2. 更新 OpenAPI、生成器、Swift DTO/端点和 DNS Store 的按需分页读取方法。
   - 原完整记录接口保持不变，继续用于节点分配、绑定选择和离线快照。
   - 新增 `0014_dns_records_pagination.sql`：名称/类型/ID 和域名区域/名称/类型/ID 联合索引。
3. DNS 记录页增加总数、页码、上一页/下一页、25/50/100 条选项、加载提示、错误显示和重试。
   - 连接、域名、搜索、排序及每页条数变化后回到第一页；手动翻页清除旧选择。
   - 页请求由服务、筛选、排序和 DNS 刷新时间标识，取消及标识检查阻止旧响应覆盖当前页面。
   - 服务切换清空页缓存和连接/域名筛选；离线时对完整缓存目录分页。
   - 从节点请求打开记录时直接选择完整目录中的记录，不依赖当前页或筛选；详情优先采用修订号或更新时间更近的记录数据。
4. 补充后端、客户端协议与网络回归，更新中英文文案和 DNS UI 夹具。
5. 本地构建 amd64 镜像，上传并验证归档、文件系统层和二进制后部署 Server1，执行公网验收。

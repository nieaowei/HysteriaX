# 0019 审计页服务端分页

日期：2026-10-09

## 目标

参照任务页实现审计页分页，搜索和排序覆盖全部历史记录，不再受最近 500 条记录的上限限制。保留本地化操作名称、对象类型和操作者搜索。

## 实施步骤（已完成）

1. 将 `GET /api/v1/audit` 响应改为 `{ items, total, page, page_size }`。
   - 默认第 1 页、每页 50 条，支持 1–200 条；非法参数返回 400，超范围页码返回最后一页，空结果返回第 1 页。
   - 搜索覆盖审计 ID、操作、操作者、对象类型和对象 ID，按字面子串忽略大小写匹配。
   - 客户端通过现有中英文显示词典，将匹配的本地化名称转换为操作、对象类型和操作者代码。后端以绑定数组执行精确匹配，并与原始搜索结果取并集。
   - 排序字段采用白名单，审计 ID 为稳定排序的第二字段。总数和页数据在同一只读、可重复读事务中读取。
2. 更新 OpenAPI、模型生成器、生成的 Swift 模型及端点；增加按需读取审计页的方法。
   - 全局刷新保存最近 200 条记录供离线快照展示，在线审计页独立读取所选页。
   - 新增 `0012_audit_pagination.sql` 创建时间/ID 联合索引。
3. 审计页增加总数、页码、上一页/下一页、25/50/100 条选项、加载状态、错误显示和失败重试。
   - 搜索、排序、每页条数及语言变化时回到第一页。
   - 取消和请求标识检查阻止旧响应覆盖当前页面；服务切换清空页缓存。
   - 离线时对已有快照分页并显示离线标识。
4. 更新客户端网络与 UI 响应夹具，补充后端、网络及本地化回归验证。
5. 在本地构建 amd64 容器镜像并上传 Server1，备份部署配置和数据库后更新 API 容器，执行公网验收。

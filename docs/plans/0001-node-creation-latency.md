# 0001：创建节点等待时间修复

日期：2026-10-16

## 问题与证据

- 服务器日志显示，创建节点后的节点列表监控汇总 SQL 耗时 39.89 秒。
- 执行计划使用全局时间索引过滤 node_id；新节点没有样本时遍历历史记录。
- macOS createNode 在收到创建响应后等待全量 refresh，延迟显示创建结果和一次性令牌。
- 当前缓存命中时原 SQL 约 180 毫秒；没有证据将当时全部延迟归因于磁盘或 CPU。

## 实施

1. 新增迁移 0031，为在线样本和代理探测样本建立按节点的最新记录索引。
2. 汇总查询使用与索引一致的 DESC NULLS LAST 排序；在线样本保留 id DESC 的同时间排序。
3. 创建成功立即更新本地节点目录、失效相关分页缓存并通知列表刷新；全量刷新在后台运行。
4. 保留服务切换的 generation 校验，避免旧服务的创建结果更新当前服务缓存。

## 验证

- PostgreSQL 18 隔离测试库：18 项 overview::integration_tests 通过。
- 新增数据库回归：两张表各 20,000 条历史样本，覆盖无样本节点、旧样本、全量及分页汇总查询、在线样本同时间排序。
- 执行计划回归要求两张样本表均使用新联合索引，以 node_id 为索引条件，每次扫描至多返回一行。
- macOS 客户端 scripts/verify-overview-network.sh 通过；新增阻塞刷新响应的网络回归，验证创建结果和一次性令牌先于刷新返回，并立即更新本地节点目录。

## 发布

此变更包含数据库迁移与 macOS 客户端修改，需分别发布后生效。迁移与查询应随同一服务版本发布。
迁移遵循现有事务迁移约定并设置 5 秒锁等待上限；新增索引期间会短暂阻塞样本表写入。
部署服务时按仓库约定在本地构建容器镜像，再推送到服务器。

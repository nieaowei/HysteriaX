# 0020 用户页服务端分页

日期：2026-10-09

## 目标

参照任务页和审计页，为用户目录增加分页、总数显示及全目录搜索和名称排序。保留节点页、授权组和概览使用完整用户目录的能力，保持用户详情、编辑、新建后的授权组管理及跨页跳转可用。

## 实施步骤（已完成）

1. 新增 `GET /api/v1/users/page`，返回 `{ items, total, page, page_size }`。
   - 默认第 1 页、每页 50 条，允许 1–200 条；非法参数返回 400，越界页码返回最后一页，空结果返回第 1 页。
   - 搜索覆盖用户名称、用户 ID 和已分配节点 ID，按字面子串忽略大小写匹配。节点搜索使用 EXISTS，避免多节点关联导致重复用户或错误总数。
   - 名称排序按大小写归一名称、原始名称和用户 ID 稳定排序，支持升降序；接口也支持创建时间排序。
   - 页数据、总数和节点/授权组来源信息在同一个只读、可重复读事务中读取。
   - 用户信息装配复用当前事务连接，单连接池也能执行，避免事务持有连接时再向连接池申请连接。
2. 更新 OpenAPI、生成器和 Swift DTO/端点，增加按需读取用户页的方法。
   - 原 `GET /api/v1/users` 保持完整目录响应，供节点、授权组、概览和既有客户端使用；此变更不破坏原用户列表接口。
   - 新增 `0013_users_pagination.sql` 的名称/ID 联合索引。
3. 用户页增加总数、页码、上一页/下一页、25/50/100 条选项、加载提示、错误显示和失败重试。
   - 搜索、排序和每页条数变化后回到第一页；手动翻页清除旧选择。
   - 页码和每页条数保存在用户/授权组的共享页面状态中，切换标签后仍保留。
   - 节点/授权组跳转直接选择完整目录中的用户，可查看不在当前页的详情；原有编辑、新建和授权组管理流程继续使用完整用户信息。
   - 服务切换清空页缓存，取消和请求标识检查防止旧响应覆盖新页面。用量查询同样检查服务地址。
   - 离线时对完整缓存目录分页并标记离线快照。
4. 更新中英文文案、客户端网络回归、授权组回归和 UI 夹具。
5. 在本地构建 amd64 镜像并上传 Server1，备份配置和数据库后更新 API 容器，验证公网分页和现有接口。

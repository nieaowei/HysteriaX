# 0045 操作内首次指纹确认与卸载失败恢复

日期：2026-10-16

## 目标

部署、同步、回滚在尚未信任 SSH 主机指纹时，直接暂停原任务等待确认，确认后重新连接并继续。卸载失败的节点能够运行 SSH 测试和确认指纹，之后由用户明确重试删除。

## 实施步骤

1. **通用等待与恢复（已完成）**：将 0044 的 `waiting_confirmation` 流程扩展到部署、同步、回滚首次信任。等待不计成功、不设置结束时间、不占用工作线程。确认在同一事务保存指纹、追加日志和审计并恢复原任务；保留任务 ID、尝试次数及原 payload。
2. **保留操作目标（已完成）**：确认仍校验节点版本及精确观测指纹。保存指纹增加节点版本并复制原配置快照；部署、同步只有目标等于当前版本时才跟随这份内容相同的快照推进，旧目标和回滚历史目标保持原值。payload 保存 `original_target_revision` 便于追溯。确认后节点显示同步中，工作线程重新校验已保存的密钥再认证。
3. **卸载失败诊断入口（已完成）**：`delete_failed` 仅允许 SSH 测试及其关联重试，`deleting` 仍拒绝新测试。诊断等待、指纹确认、测试成功或认证失败均保留卸载失败状态；测试不自动恢复卸载或调度其他远程操作。用户可返回节点列表明确重试删除。并发开始删除时，过期诊断结果不得覆盖删除状态。
4. **客户端及契约（已完成）**：使用通用指纹确认卡片，按任务类型显示“信任并继续测试／部署／同步／回滚”。补充卸载失败诊断提示和操作可用性规则；同步 OpenAPI、生成的 Swift 请求、Xcode 文件引用及中英文文案。

## 验证

- `cargo test --workspace`：231 项通过，1 项原有 benchmark 跳过。
- 最终确认后节点显示状态调整后，追加执行任务模块 24 项测试，全部通过。
- 真实本地 SSH 协议模拟测试覆盖三类任务首次确认、确认前零认证、服务重启保留等待、原 ID 和尝试次数、配置内容一致及回滚目标不变。恢复后实际执行认证和环境检查，由测试服务器在只读前置检查末尾注入错误，避免下载或远程安装。
- 卸载失败恢复覆盖初次缺少指纹、确认后诊断成功、失败后的关联重试、诊断成功后手动重试卸载，以及并发删除不被旧结果覆盖。
- 指纹客户端测试覆盖四类任务使用同一确认接口，无额外 PATCH 或重试任务；节点任务反馈测试、展示文案测试、1375 条双语资源覆盖与 API 生成一致性检查通过。
- macOS Xcode Debug 构建通过；未运行完整容器部署矩阵或远程现场验收，未部署服务。

## 范围

已有指纹发生变化时，部署、同步、回滚仍中止并保留原失败确认流程。卸载任务本身仍由用户明确重试；本次补齐其失败后的诊断入口。不新增数据库迁移，复用 0030 的等待状态。

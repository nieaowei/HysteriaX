# 0044 SSH 测试指纹确认与继续执行

日期：2026-10-16

## 目标

一次 SSH 测试使用同一个任务 ID 完成连接、等待用户确认指纹、重新连接校验、认证和环境检查。确认操作不创建重试任务，也不增加尝试次数。

## 实施步骤

1. **持久化等待状态（已完成）**：新增 `waiting_confirmation` 任务状态。首次获取指纹和发现指纹变更都暂停原 SSH 测试；不记录为成功，不设置结束时间，不占用工作线程。服务重启保留等待状态。
2. **原子确认与恢复（已完成）**：新增 `POST /jobs/{id}/confirm-fingerprint`。校验任务状态、实际观测指纹、原指纹和节点版本，在同一事务保存指纹、复制配置版本、恢复原任务、追加事件、日志和审计。恢复时重新连接，并在认证前验证指纹。
3. **客户端连续操作（已完成）**：任务详情显示新旧指纹、核对勾选项和“信任并继续测试”。提交期间防止重复点击；确认后继续展示原任务。补充中英文状态和审计文案，保留旧服务任务以及其他操作失败后的原有确认入口。
4. **并发保护与验证（已完成）**：节点编辑、新测试或删除取消过期等待；确认后节点发生变更时禁止旧测试继续认证或覆盖节点结果。认证失败仍记录在原任务，节点不再误报待确认指纹。更新 OpenAPI、生成的 Swift 模型、Xcode 工程与五个现场验收脚本。

## 验证

- PostgreSQL 隔离 schema 和真实本地 SSH 协议模拟服务器：确认前无认证、首次信任与密钥变更、重启后继续、任务 ID 与尝试次数不变、重复与过期确认拒绝、事务失败回滚、认证失败、节点编辑及删除、过期工作结果不得覆盖节点。
- `cargo test --workspace`：227 项通过、1 项原有 benchmark 跳过；最终失败状态调整后追加运行任务模块 20 项测试，全部通过。
- macOS 指纹客户端测试、节点任务反馈测试、展示文案测试、双语资源覆盖检查、Swift API 生成一致性检查与 Xcode Debug 构建。
- 五个现场验收脚本完成流程更新和 Python 语法检查；本次未运行容器部署矩阵或远程现场验收。

# 0012 — 概览窗口缩放性能修复

日期：2026-10-04（Asia/Shanghai）

## 问题与定位

概览同时挂载三个 tab，以透明度隐藏非当前内容；隐藏页仍含图表并参与布局。概况和服务器卡片嵌套多套 ViewThatFits 候选树，缩放时重复测量与更新。时间戳解析还反复创建 ISO8601DateFormatter。

使用同一静态夹具、关闭网络的离屏缩放对照，每种场景预热后测量 96 次并复测。650–1070 点宽度范围中，旧概览平均布局耗时 95.1 ms（复测 96.9 ms），隐藏 tab 测量 775 次；仅挂载当前 tab 降为 51.7 ms。另一个保持宽布局的对照中，移除嵌套候选树后从 58.2 ms 降为 13.8 ms。

## 实施步骤及结果

1. 已改为只挂载当前 tab。OverviewSceneState / OverviewTabState 独立保存时间范围、来源、节点、事项展开状态和滚动记录，避免将状态保留与视图常驻绑定。
2. 已将概况双列、指标网格、服务器身份/资源/采集信息及趋势筛选控件改为单一内容树的原生 SwiftUI Layout。根据实际宽度直接决定排列；缓存本次测量供放置使用，每次尺寸计算仍重新测量内容，避免数据或展开状态变化时使用过期高度。
3. 已保留 280 点待办窄列、636 点双列边界、768 点指标四列边界，以及服务器信息 420 / 480 点排列边界。更窄窗口保持竖排及两列资源指标。
4. 已将滚动偏移保存到独立状态，滚动写入不触发整个页面更新；页面卸载后停止记录，重新挂载恢复位置，额度快捷跳转按请求编号只处理一次。
5. 已预计算 OverviewHistoryDisplay：桶的 Date / 结束 Date、图表边界、缺失计数、节点覆盖摘要与更新时间文本，只在历史数据变化时生成。
6. 已用受 NSLock 保护的共享 ISO 格式化器及有数量上限的日期缓存替代反复构造格式化器。节点套餐日期解析同步复用，并更新对应验证脚本依赖。
7. 已将管理服务器、卡片容器、tab 滚动页、布局器和节点详情拆为独立视图。节点详情由稳定概览根视图呈现，选择状态由场景保存，避免卸载内容层承载弹窗。
8. 已更新 UI 自动化：验证当前页的滚动容器、tab 时间范围及滚动位置保持、非当前页面未挂载、详情和通知关闭及快捷跳转。

## 验证结果

- 同样的离屏缩放序列：修复后运行概况平均布局 4.49 ms，复测 4.66 ms；布局与离屏渲染合计约 14.4–14.9 ms。原始概览约 95–97 ms / 106–107 ms。
- 同组验证中，流量趋势平均布局 4.40 ms、质量趋势 5.93 ms、任务页 5.66 ms。无隐藏 tab 测量，缩放阶段没有调用日期解析。
- 以上是同机离屏测试，不是实际拖动窗口的 FPS；正式客户端已按相同代码构建。
- 可复用测量入口：`scripts/verify-overview-resize.sh`，结果：`apps/macos/.build/overview-resize/results.json`。
- 客户端渲染/预计算/状态/日期解析检查通过，覆盖明暗主题、宽窄布局和图表柱形。
- 客户端请求取消、服务切换、缓存隔离和版本能力检查通过。
- 节点套餐客户端测试通过，包括草稿、缓存、API 及通知持久化去重。
- UI 自动化通过：`apps/macos/.build/overview-ui-1791104472.xcresult`，验证筛选和滚动恢复以及节点详情、通知和导航。
- 本次为客户端性能修改，不需要更新服务器镜像。

## 最终验收

正式代码再次复测：运行概况平均布局 4.53 ms（复测 4.47 ms），流量趋势 4.18 ms，质量趋势 5.69 ms，同组任务页 5.47 ms。运行概况布局与离屏渲染合计约 14.4 ms。原始与最终原始结果分别保存为 `0012_overview_resize_before.json`、`0012_overview_resize_after.json`。

Xcode Debug 构建并启动验证通过，修复后的正式客户端已启动。生成模型一致性与 diff 空白检查通过。

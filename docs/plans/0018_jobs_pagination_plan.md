# 0018 任务页服务端分页

日期：2026-10-09

## 目标

任务页可以遍历全部历史任务，不再受最近 200 条记录的限制。搜索和排序在服务端覆盖全部历史。允许调整后端响应结构，客户端和服务端须一起更新。

## 实施步骤（已完成）

1. 将 `GET /api/v1/jobs` 的数组响应改为 `{ items, total, page, page_size }`，接受 `page`、`page_size`、`q`、`sort`、`order`。
   - 默认第 1 页、每页 50 条；每页条数范围为 1–200。
   - 参数无效返回 400；页码超出结果范围时返回最后一页；空结果返回第 1 页。
   - 搜索覆盖任务、节点及资源标识/名称、类型、阶段、状态、失败原因；搜索词按字面子串匹配。
   - 排序字段采用白名单，任务 ID 作为稳定排序的第二字段。总数和当前页在同一只读、可重复读事务中查询。
2. 更新 OpenAPI、Swift 模型生成器及生成文件，增加按需读取任务页的方法。
   - 全局刷新继续读取最近 200 条作为节点任务反馈和离线快照，任务页独立读取所选页。
   - 增加 `0011_jobs_pagination.sql` 创建时间/ID 联合索引，支持默认分页排序。
3. 在任务页增加总数、页码、上一页/下一页、25/50/100 条选项、加载状态和失败重试。
   - 搜索、排序或每页条数改变时回到第一页；翻页清除旧选择。
   - 请求取消及请求标识检查防止过时列表/详情响应覆盖新状态；服务切换清空页缓存。
   - 节点页任务跳转独立读取详情，可打开不在当前页的任务。
   - 离线时对现有快照分页并明确标注离线快照。
4. 更新中英文文案、客户端响应夹具和受影响的实时验收脚本。实时脚本遍历服务端分页后再执行已有任务检查。

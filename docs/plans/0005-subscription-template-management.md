# 0005：订阅模板与完整可视化配置管理

状态：已完成。计划日期：2026-10-18；实施与最终验收日期：2026-10-18。

## 1. 目标与交付边界

一次交付全局多模板、完整可视化编辑、源码双向同步、平台覆盖、导入导出、预览校验、发布及回滚。

- 一个模板对应 Mihomo 或 sing-box 一种格式，不绑定用户或授权组；用户权限只决定可注入的节点。
- 订阅地址携带模板 ID，始终使用该模板最新发布版本；保存草稿不影响订阅，不提供固定历史版本地址。
- 覆盖 Hysteria2 订阅所需的全部公共配置字段，不扩展其他代理协议的手工节点管理。
- 导入现有配置时保留策略、替换节点，提供引用映射和变更预览。
- 源码与表单保持配置语义一致；保留未知字段、数组顺序，不保留原始注释与排版。
- 允许调整管理 API、数据库结构和旧订阅契约，Mac 与服务端同步升级；保持现有代理内核支持范围。
- 按目标平台进行结构与语义校验；运行时不调用真实内核，不将真实内核检查作为发布门禁。

## 2. 配置模型与字段覆盖

### 2.1 字段目录

- 建立版本化字段目录，以项目固定验证版本 Mihomo v1.19.31、sing-box v1.14.2 的配置定义为依据，记录字段类型、枚举、默认值、互斥条件、引用关系、平台和版本限制。验证基线不等于提高已有订阅内核最低版本。
- 为支持范围内的每个字段提供专用表单：基础与日志、监听与入站、TUN、DNS、代理组、规则集、分流规则、控制 API、缓存、证书、NTP 及其他公共高级设置。按配置类型显示对应字段，不以通用 JSON 编辑器代替已支持字段的表单。
- 节点连接参数由已部署配置生成，展示为只读注入内容；不在模板中维护用户密码、mTLS 私钥等动态材料。
- 字段目录同时驱动服务端校验和客户端字段元数据；建立字段覆盖检查，防止出现“服务端支持、表单遗漏”。
- 未知字段保留在所属配置层中，集中显示为“未验证字段”，可通过源码编辑；发布时给出警告，不将其标记为已支持或已验证平台兼容。

### 2.2 单一配置来源

- 模板采用结构化文档，包含原生配置对象、平台覆盖和独立节点注入规则，不使用任意文本替换。
- 表单和源码操作同一份文档。源码解析、规范化和输出统一由服务端完成，避免 Swift 与 Rust 使用不同 YAML 解释规则。
- 原生 YAML/JSON 源码编辑明确作用于“通用配置”或选定的平台覆盖层；平台覆盖的移除操作和节点注入规则通过独立结构化区域编辑。完整模板导出包含全部层和注入规则，避免切换源码时丢失元数据。
- 草稿可保存语义未完成的配置；语法无效的源码暂存于客户端编辑缓冲区，不覆盖已解析文档。

## 3. 平台配置与生成规则

采用“通用配置＋平台覆盖”，替换原先生成后自动过滤已知不支持字段的设计。平台差异必须可见、可编辑，不得将已知无效的设置静默删除后继续下发。

### 3.1 配置层与字段归属

- 每个模板包含通用配置，以及 Linux/OpenWrt、macOS、Windows、Android、iOS 的覆盖。OpenWrt 在当前能力模型中使用 Linux 平台配置，界面名称明确显示 Linux/OpenWrt。
- 字段目录标明适用平台、适用版本和是否由客户端接管；切换编辑目标后，只展示该平台允许编辑的字段，并保留查看其他平台设置的入口。
- 各平台通用字段（如规则、代理组）默认继承通用配置，可以在平台层覆盖。
- 仅部分平台支持的字段（如 TProxy）只允许在支持的平台层设置，不写入其他平台输出。通用层不允许设置会使其他目标平台无效的已知字段。
- 各平台取值不同的字段（如接口名称）允许在平台层分别设置，不强制共用默认值。
- 由客户端接管的字段（如移动端部分 TUN 选项）标明由客户端管理，在对应平台禁止配置并且不输出冲突字段。
- 初始平台能力以现有项目适配行为为基础，逐字段核对固定版本定义；不凭字段名称推断支持范围。

### 3.2 覆盖语义

- 覆盖明确区分“继承”“设置”“移除”；留空、显式 null、false、0 和空列表不替代这些操作。
- 对象字段按路径覆盖，数组默认整体替换，不进行按下标或名称的隐式合并。编辑器展示继承数组，修改后形成该平台的完整数组覆盖。
- 移除使用独立字段路径列表表达，不使用 null 作为删除标记；设置与移除同一路径属于配置错误。数组内部修改通过替换整个数组表达。
- 平台层新增的组、规则集或监听引用必须在该平台最终配置中有效；重命名和删除操作检查所有配置层中的引用，不只检查当前可见层。
- 界面逐字段显示值的来源和覆盖状态，并支持恢复继承。预览列出平台差异，例如“此值由 Windows 覆盖”及“TProxy 仅在 Linux/OpenWrt 配置”。

### 3.3 平台选择与最终生成

生成顺序固定为：访问资格校验 → 读取发布版本 → 解析目标平台 → 合并通用配置与平台覆盖 → 获取并按客户端能力筛选节点 → 动态注入 → 最终结构、平台与引用校验 → 序列化。

- 显式 `platform` 优先于 UA；`platform=auto` 或省略时尝试识别 UA。无效或重复参数返回 400。
- 无法识别平台时显示平台选择页，不默认套用 Linux 配置；选中平台后保留模板和格式参数，返回可直接复制的明确平台地址。
- Mac 复制订阅地址和导出最终配置时，要求明确选择目标平台；记忆上次选择作为便利，不自动将 Mac 所在平台视为目标设备。
- 发布前对五类目标平台分别检查合并后的结构、字段适用性、组引用、规则集引用、默认项和循环引用。节点依赖使用无节点及代表性动态节点集合验证；真实用户节点变化时仍在每次生成中完成最终校验。
- 不进行静默平台修复；已发布配置若因实际节点集合变化产生无效引用，返回 422 及可定位诊断，不下发损坏配置。
- 不调用真实内核作为运行时校验或发布检查，不声称结构校验证明所有平台运行可用。

## 4. 动态节点与统一渲染

- 节点选择规则支持全部可用节点、指定节点 ID、名称包含/前缀匹配、排除条件、排序和默认优选条件；只作用于当前用户已授权且符合订阅资格的节点。
- 代理组可混合引用其他组、内置动作和动态节点集合。组重命名同步更新引用，删除仍被引用的对象时阻止操作并定位引用。
- 去除代码中的地区名称和固定组位置逻辑，将现有策略转换为种子模板中的显式选择规则。
- 动态节点使用含稳定节点标识的输出名称，避免同名节点及手工组名称冲突；模板组不得占用系统保留命名空间。
- 动态集合为空时默认使用直连兜底，也可配置为明确报错；存在授权节点但全部不兼容时保留现有 422 行为。
- 预览、下载和导出共用同一渲染流水线；平台层替换代理组后，节点注入规则按最终组名解析，缺失目标组必须报错。

## 5. 服务端、存储与 API

### 5.1 存储和版本

- 新增模板、草稿及不可变发布版本；模板格式创建后不可修改，跨格式转换通过新建模板完成。
- 文档及历史内容使用现有主密钥加密存储，列表只返回元数据；审计记录操作、版本和结果，不记录配置正文或秘密值。
- 所有写操作携带 `expected_revision`，冲突返回 409，界面保留本地修改并支持查看差异。
- 发布原子创建版本并切换生效指针；回滚将历史内容发布为新版本，不改写历史，且重新执行当前校验。
- 采用归档替代物理删除。默认模板归档前必须指定同格式替代项；归档模板的显式订阅地址返回 404。

### 5.2 管理 API

在 `/api/v1` 下新增以下接口，并同步 OpenAPI 与 Swift 生成模型：

- `/subscription-templates`：分页列表、新建；`/{id}`：详情、修改元数据和归档。
- `/{id}/draft`：读取和保存包含通用配置、平台覆盖及注入规则的草稿。
- `/{id}/validate`、`/{id}/preview`：结构与语义校验、按用户和目标平台预览。
- `/{id}/publish`、`/{id}/versions`、`/{id}/rollback`：发布、历史和回滚。
- 配套字段目录、源码解析/序列化、文件导入分析及模板导出接口。

预览可选择用户、平台和内核版本；返回配置文本、值来源、平台覆盖差异、节点筛选原因及带配置层和字段路径的诊断。默认脱敏，管理员可显式查看完整结果；预览响应禁止缓存。

### 5.3 公开订阅契约

- 新地址：`/sub/{token}?template={id}&platform=…`。格式由模板决定，与显式 `format` 冲突时返回 400。
- 未指定模板时，按现有客户端识别结果使用相应格式的全局默认模板；未知客户端显示已发布模板、格式和平台选择页。
- URI/Base64 继续直接根据节点生成，不参与模板和平台覆盖；与模板参数组合时返回 400，输出节点链接时无需平台选择。
- 移除旧 `/clash.yaml` 专用接口和管理响应中的旧地址回退字段，统一返回新地址结构。
- 缓存键包含模板 ID、发布版本、目标平台、客户端能力及既有节点/凭据状态；发布、回滚、默认项切换和归档后，新请求立即使用新状态。
- 实时资格校验、令牌撤销、用户到期和额度限制继续生效，模板与平台覆盖都不能扩大节点权限。

## 6. Mac 界面与操作流程

- 主导航新增“订阅模板”，采用模板列表、配置编辑区及预览/诊断检查器；独立组织模型、功能 Store 和各配置模块。
- 提供格式筛选、新建、复制、默认项设置、归档、导入导出和历史版本入口。
- 编辑区提供“通用配置 / 目标平台”选择及“可视化 / 源码”切换，支持字段搜索、恢复继承、恢复默认、数组增删排序、条件字段和引用选择。
- 每个可选字段区分未设置与显式 false、0、空列表；平台覆盖增加继承、设置、移除的明确控件。
- 支持撤销/重做、未保存修改提示、草稿保存状态和发布版本对比。源码无效时保留输入并显示错误，阻止切换覆盖表单。
- 导入先展示节点移除、平台字段归属及引用映射。已知平台专用字段移入对应平台覆盖；无法确定归属的字段保留并要求处理诊断，不静默丢弃。
- 确认映射后写入草稿，未解决的已知非法引用或平台字段阻止发布。其他协议节点同样移除并明确列出。
- “导出模板”输出可再次导入的完整配置包，包含平台覆盖和注入规则；“导出最终配置”按所选用户和平台输出原生 YAML/JSON。
- 用户订阅菜单增加模板与平台选择，复制明确的订阅地址；不将选择保存为用户或授权组绑定。
- 中英文文案、键盘操作、无障碍标识、加载失败及 409 冲突处理随功能一起完成。

## 7. 测试与验收

- 字段覆盖：支持字段均具备专用表单、目录元数据及适用平台声明；目录与表单绑定缺失时检查失败。
- 配置往返：覆盖嵌套对象、联合类型、可选值、规则顺序、未知字段保留，以及源码—表单—保存—重载的语义一致性。
- 平台覆盖：覆盖继承、设置、移除、数组整体替换、恢复继承、对象嵌套、平台专用字段、客户端接管字段和跨层引用重命名。
- 平台输出：覆盖五类目标平台及 OpenWrt 别名，验证字段来源和差异明细；显式平台优先、UA 自动识别、未知平台选择页、参数错误均有测试。
- 引用与注入：覆盖循环引用、缺失规则集、同名节点、地区选择、空集合、已删除节点、平台组覆盖和默认项失效。
- 订阅行为：覆盖用户权限隔离、现有高级节点能力、全部节点不兼容、URI/Base64、令牌撤销及每个平台之间的缓存隔离。
- 发布一致性：覆盖草稿隔离、并发编辑/发布、回滚、归档、默认项切换、服务重启及缓存失效。
- UI 验收：完成导入、全字段表单编辑、平台覆盖、源码切换、错误定位、用户与平台预览、发布、复制地址、下载和回滚的端到端流程。
- CI 保留固定内核对支持平台测试样例的配置检查；不作为运行时发布门禁，不据此声称其他平台已获真实运行验证。

## 8. 实施顺序、迁移与交付

1. 完成字段目录、平台能力清单、配置模型及字段覆盖检查。
2. 实现存储、覆盖合并、校验、注入、渲染和管理 API。
3. 完成所有专用表单、平台编辑、源码同步和完整操作流程。
4. 切换公开订阅与客户端入口，完成迁移、验证和文档后统一交付。

- 新增数据库迁移，将现有两个内置模板初始化为已发布默认模板；按现有适配行为拆分通用配置和平台覆盖。保留现有节点、用户、授权及订阅令牌，不保留旧订阅接口兼容层。
- 内置文件仅作为首次初始化资源，运行时不作为隐藏回退配置。备份恢复纳入模板和版本。
- 完成 Rust、OpenAPI 生成一致性、订阅集成及 Mac 构建/UI 检查；更新订阅、架构和升级文档，说明旧链接和旧 Mac 客户端的破坏性变更。
- 本计划提前落盘供实施使用，实施完成后按项目要求在本文更新完成状态、实际变更及验证结果。
- 本计划不包含服务器部署；后续如部署，必须本地构建容器镜像并推送服务器。

完成标准：支持范围内的订阅配置全部可通过专用表单管理；平台差异可明确编辑和预览；导入、源码编辑及发布不丢失配置语义；修改模板无需改代码或重新部署；发布和回滚通过同一订阅地址验证生效。

- 服务端实现版本化字段目录、原生默认值/枚举、平台条件、明确覆盖操作、原生 YAML/JSONC 解析、逻辑规则/跨层引用校验、节点选择与稳定命名、统一渲染、管理 API、原子发布、回滚新版本、归档和默认替换。
- Mac 提供独立模型与 Store、类型化字段及 Mihomo 规则控件、字段搜索、源代码同步、继承/设置/移除、撤销重做、诊断定位、用户/平台预览、编辑导入映射、完整包及最终配置导出、历史对比/回滚和明确订阅地址选择。
- 未知字段、数组顺序、显式 false/0/null/空列表及 UInt64 均按文档模型保留。无效源码不覆盖已解析文档；草稿允许语义未完成；冲突保留本地内容；跨服务连接变更阻断旧草稿误提交。
- 已使用的组、规则集等命名对象删除时检查五个平台合并结果并定位现有引用；重命名更新所有层。预览返回兼容性和选择规则排除原因，Mihomo 优选节点通过首项选择生效。
- 公开订阅读取模板当前发布版本和明确平台；URI/Base64 保留独立路径。旧 `/clash.yaml` 与 `auto_url` 回退已移除，调用方、OpenAPI、Swift 生成模型及升级说明已同步。
- 审计覆盖成功和失败、修订号、发布/来源版本与错误码，排除正文和秘密值。整个数据库的备份恢复包含新表及初始化状态。

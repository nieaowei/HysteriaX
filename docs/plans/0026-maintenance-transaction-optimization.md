# 后台维护事务争用优化方案

日期：2026-11-06。状态：第一批已于 09:14:40 部署，后续空闲清理样本已超过 100 次；第二批仅取消扫描的发现/入队事务已于 18:34:50 部署，约 31 分钟健康、接口和采样新鲜度核对通过，稳定期仍有独立采样窗口失败。整体性能优化尚未验收，jobs 隔离调整及第三批暂缓。

## 依据与目标

以 0025 的生产观察为基线：94 次 40001 尝试涉及 83 个调用，均恢复；60 次在 Work::finish_on 的 background_work 状态 UPDATE 检测到。稳定 25 分钟中 jobs 维护 37/211 调用重试，过期凭据清理 14/23，取消扫描 14/436。清理样本较少；检测位置不等于完整冲突起因，不能认定所有事件均来自同一索引页。

目标是减少维护事务的无效往返、串行化读写依赖和连接占用。按 10 万用户、1 万节点设计：批次有界、按资源并发，不引入全局维护互斥或随节点数量增长的逐节点空轮询。保留六次尝试预算和现有结构化观测。

## 第一批：合并校验、优化空清理路径

### 1. 将租约释放的校验与 UPDATE 合并

当前公共事务入口调用 execution::guard_current；业务又调用 Work::guard_on；Work::finish_on 再次 guard；Execution::release 还执行一次 SELECT guard 后才 UPDATE。同一批次存在重复往返，但不能把随时间变化的有效期校验简单缓存掉。

在当前受监督事务的入口已经持有目标租约锁时，将 Execution::release 的重复 SELECT guard + UPDATE 改成带完整 owner、generation、work_id、epoch、未过期、未 blocked 和未决远程操作排除条件的单条 UPDATE，并检查受影响行数。入口没有持锁证明的调用继续先在独立语句中 guard、再 UPDATE，确保 READ COMMITTED 下能看见等待锁期间刚提交的远程操作。保留执行作用域验证、released intent、提交前终态验证及原子回滚。身份不匹配、过期或远程结果未知都必须拒绝释放。

随后评估将入口的多个租约 guard 合并成一次有序批量锁定与身份校验；缺任一租约必须整体失败。维持原资源锁顺序，不引入先锁 work 再锁 lease 的相反顺序。第一批不使用跨事务缓存或“校验过就永久有效”的标记。

主要位置：execution/mod.rs、execution/finalization.rs、background/maintenance.rs。预计先减少数据库往返和锁持有时间；冲突下降幅度需要对照测量，不能承诺仅此就消除工作索引页依赖。

### 2. 凭据清理增加安全的空批次路径

原 retention::prune_work 无论有无候选都进入 SERIALIZABLE，并读多个引用集合、修改游标、收尾工作。实施时使用上轮已完成的全量空扫描写入 `idle` 提示；只有持有该提示的下一轮才先进入 READ COMMITTED 探测，首次扫描及持续非空分页保持原有单个 SERIALIZABLE 事务。提示不构成删除授权。在受原工作租约保护的 READ COMMITTED 事务中保留 reference_index::assert_clean_on 的拒绝语义，再检查候选：

- 没有候选：只重置/推进原有空页游标状态并确认本轮工作，沿用原有空页 60 秒、翻页回绕 1 秒的调度语义，不删除任何凭据或版本。
- 有候选：结束预检查事务，重新进入原 SERIALIZABLE 删除事务；使用新快照重新选择、锁定和验证候选，不能把预检查结果当作删除授权。
- 预检查失败或失去所有权：不确认完成，按原机制恢复。

空结果之后并发出现新候选，只允许延后至原有下一轮，不会误删。已确认空闲后重新出现候选的那一轮会多一次探测事务；持续非空分页不增加探测。空页尾部回绕时清除 idle 提示并按原有 1 秒间隔回到完整扫描，避免跳过早期版本。需同时测空/非空吞吐，不能为了降低冲突数牺牲清理进度。

实际删除暂保留 SERIALIZABLE。CANDIDATES 涉及 activation、active probe、reference edge、batch、node 等跨表 NOT EXISTS；当前父凭据 FOR KEY SHARE 不能自动证明所有引用写入都被排斥。

主要位置：credentials/retention.rs、retention_tests.rs。第一批不改 schema，不需要数据迁移。

## 第二批：逐条替换不必要的串行化维护事务

优先审核 jobs::maintenance_work 的 recovery / kick_schedule，再审核 cancelled::scan。为每条路径列出读取条件、所有并发写入方、锁顺序、唯一约束及允许的延期范围。

只有证明任务所有权、取消、重复入队、游标和事件一致性由精确锁/约束完整保护，才切换到现有 db::write。对于“未发现某行”的判断，需要原子条件写入、唯一约束或共同锁协议；不能因为读到的已有行加了锁，就假设不存在的行也得到保护。扫描发现仅作为提示，写入时重新确认仍有资格。

业务变更、审计/事件、子任务指针、游标、租约释放及工作确认保持同事务提交；继续拒绝旧 owner/generation/epoch、取消后的写入和未核验远程操作。锁协议证明不成立的分支保留 SERIALIZABLE，不将整个模块一刀切。

凭据实际删除的隔离调整另行审核全部引用写入方，不放进这一批。缓存失效触发器在生产稳定阶段没有持续高冲突证据，暂不优先改动。

## 第三批：减少无工作轮询

将持久化 available_at / 最早到期工作用于计算下一次唤醒；对同类 ensure/claim 合并有界操作，加入有上限的抖动，避免多个维护循环同时争用连接。优先处理清理等本来就允许分钟级空闲等待的任务。

本地 next_due 只是调度提示，数据库条件仍是领取依据。跨实例唤醒需有通知及有限间隔的补查，不能仅靠进程内缓存；有待处理任务时继续原有分页速率。jobs 恢复、取消扫描等路径保持既有处理延迟上限，不能统一把 1 秒轮询改成 60 秒。

不先通过扩大连接池、增加重试次数、修改 work ID 或强制索引掩盖争用。若仍有明显元数据页级依赖，再凭复现及计划证据单独评估存储布局；需要 schema 变更时另做版本迁移和测试环境一次性迁移工具。

## 验证与验收

实施后先运行受影响的真实数据库专项：不同工作并发收尾、同一工作竞争、旧身份/过期拒绝、取消、未知远程结果屏障、事务失败时业务与确认一起回滚；租约在批量校验/释放/提交期间过期；预检查后出现候选或引用；非空清理与引用发布并发；双实例唤醒和崩溃接管。

性能对照沿用已复现的工作元数据争用夹具和实际后台循环，保持基线/候选版本的输入、数据库版本、并发、延迟和数据规模相同，分别测空清理、非空清理及混合负载。记录每调用 SQL 次数、事务耗时、冲突尝试、完成工作量、连接等待和续租结果。历史数据规模场景与 10 万用户/1 万节点容量场景分开报告。

目标而非已验证结果：同负载实验中目标维护路径的冲突尝试/调用下降至少 80%，事务往返减少，吞吐及处理及时性不下降；业务不变量、重试耗尽、错误释放和续租失败不能恶化。生产按同口径逐路径复核，不要求所有 40001 归零。凭据清理至少收集 100 次调用，避免用当前 23 次样本宣称达标；同时记录实际工作量和负载差异。

只有代码发生相应改动后才运行这些测试；方案阶段不重复全量测试。共享执行协议发生改动时完成对应回归，再执行项目要求的检查。0025 已记录的并发签发间歇失败继续单列，不能静默豁免或弱化断言。

## 第一批实施记录

Execution::release 的快路径使用条件 UPDATE，依赖当前事务入口已锁定目标租约的证明；Attempt 在 guard_current 成功后创建，记录当时捕获的租约身份，并验证连接及生命周期。证明缺失时保留原先分语句加锁和检查；更新未成功时重新校验身份，保留失去租约时 Err、身份有效但远程结果未核验时 Ok(false) 的区分，成功后才记录 released intent。业务事务、终态验证与生命周期交接保持。

初版将 guard 与 UPDATE 放进同一物化 CTE；代码审查发现该语句等待行锁后仍可能使用旧快照，漏掉锁持有者在等待期间提交的远程 intent，因此弃用该版本并补充确定性并发回归。初版没有部署，其性能数据单独保留，不作为最终版本验收。

凭据清理按上面的 idle 提示分流；真实删除集中在 prune_candidates，并始终重新选择、锁定和检查引用，保持 SERIALIZABLE。没有修改 schema、重试预算或原调度间隔。入口批量 guard 暂未替换：本次清理热点只有单个工作租约，先用释放合并和空路径分流取得可单独测量的收益，后续依据多租约路径指标决定是否扩大公共入口改动。

新增 10 项正确性用例，覆盖各身份字段、blocked/过期、三种未知远程操作状态、等待中 owner 被替换、等待期间提交远程 intent、空页隔离与原间隔、空后出现候选、探测后新增引用、游标回绕、引用索引未就绪、旧 owner 拒绝及空确认回滚。快路径持锁证明修正后重新完成受影响回归，完整回归及最终性能结果如下。

性能材料放在本地 target/maintenance-optimization/。正式夹具在 credentials/retention_benchmarks.rs（显式忽略），控制入口在 tests/performance/benchmark-maintenance-transactions.py。首轮计数含监督器及连接初始化，修正夹具后预建连接、单独统计事务 SQL 并反转版本顺序复核；两种口径分别保留，不能混合汇总。首轮非空耗时差异约 1.2%，尚未作为退化或改善结论。清理测试 schema 的初版脚本一次性 DROP 全部 schema 触及本地锁表上限，已改成逐 schema 提交，不影响生产或业务回归结果。

# 0007 编译期订阅校验器与缓存复用

状态：已实施并部署至 Server1。日期：2026-10-19。

## 目标

采用评估通过的 jsonschema 0.59.0 编译期宏，把固定规则生成的机器码放在独立内部 crate 中。普通后端源码变更复用其编译结果；规则或准备逻辑变更必须重编译，并保留构建门禁和全部业务校验。

## 实施内容

1. 新建 `hysteriax-template-validator` 内部 crate，由构建脚本读取既有目录和共享准备函数，自检原始/准备后规则并生成宏声明。
2. 服务端使用借用 JSON Value 的错误路径接口。平台、引用、权限、警告、发布和输出逻辑继续由原模块负责，不引入会丢失未知字段的类型转换。
3. 退出 jsonschema 0.33.0 生产补丁。锁定新版依赖，保留许可证；后续清理删除旧源码及诊断工程，仅在 `tests/fixtures/template-validator` 保留 CI 使用的兼容性夹具。
4. 用隔离夹具验证普通客户端改动时 Cargo 返回 fresh 且 rlib 哈希/mtime 不变；合法规则变更会重编译并改变实际判断；损坏规则导致构建失败。
5. 对实际内部 crate 执行冻结的 1,046 例结果/错误路径回归，再运行工作区、固定内核及 Linux 进程内存验收。
6. 本地构建 amd64 镜像，验证通过后传送至测试服务，保留旧镜像及配置并检查实际预览与 readyz。

## 交付边界

- 不改变 Schema 的原始来源、平台范围、字段保留策略、数据库或节点配置。
- 生成 crate 对服务端无依赖；构建只跟踪显式 Schema 输入。规则、编译器、特性或依赖版本变化可以正确使缓存失效。
- 本次不改写发布事务、可视化编辑器或数据库参数。

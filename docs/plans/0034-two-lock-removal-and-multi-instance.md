# HysteriaX v2：移除全局写锁与单实例运行锁

## 1. 目标与边界

彻底移除应用级全局写锁和单实例运行锁，使多个全功能服务实例能够同时提供 API、采集、任务执行和后台维护。保留 PostgreSQL 的事务、行锁、唯一约束及资源级互斥，不再依赖任何覆盖全部业务写入或整个服务生命周期的应用锁。

已确认的约束：

- 保留全部业务配置、凭据、累计用量、历史采样、任务、事件及审计数据。
- 允许破坏性 schema 和协议变更；服务端与新版 macOS 客户端一起适配，不兼容旧客户端。
- 采用维护停机切换，禁止新旧服务混跑。
- 缓存直接重构并保留，消除全局版本计数热点。
- 数据库内工作自动接管；远端副作用不明确时先核验，无法确认则等待人工恢复。
- 首版验收并发正确性和故障恢复，记录性能对比，不承诺固定吞吐。
- 本次不引入时序数据库、消息中间件、节点常驻 Agent，也不同时实施历史表分区或更改保留期限。

## 2. 并发事务与缓存重构

**统一事务规则**

- 删除两把锁的常量、获取函数、连接监测和启动退出逻辑，同时移除凭据引用模块中写死的同一锁调用。
- 管理侧跨实体变更采用 `SERIALIZABLE` 事务；计费及队列处理采用显式资源行锁和条件更新。所有冲突判断都在事务内执行。
- 数据库事务改为可重试的纯数据库闭包；对 `40001`、`40P01` 最多重试五次并随机退避。业务 revision 冲突返回 409，重试耗尽返回 503。SSH、DNS 请求及其他外部副作用不得进入重试闭包。
- 多资源加锁使用统一顺序，同类实体按 ID 排序。唯一约束作为最终防线，不能只依赖“先查询是否存在”。

**记账与配额**

- 采样结果先持久化为具有稳定 `sample_id` 的采样批次，再按最多 500 个用户项目处理；处理进度与计费结果同事务提交。
- 对采样项目建立唯一约束，重复处理不重复计费；基线、用量、明细、撤销义务原子提交。
- 用户累计用量改为数据库原子累加，保留现有饱和计数和重启、计数器回退语义。
- 配额重置、人工用量修正和采样使用相同的用户／节点保护规则。用户重置按数据库入账顺序划分周期，不清空节点累计计数基线；节点修正继续通过 generation 拒绝过期采样。
- 保留在线人数跨节点去重、失败与零值区别、采样覆盖率及当前计费规则。

**统计与凭据引用**

- 所有 dirty 队列改为带版本的键级队列；源数据变更与 dirty 版本递增同事务提交。
- 刷新事务通过行锁领取有限批次，持锁完成刷新及确认，禁止无条件清空整张 dirty 表，确保刷新期间的新变更不会丢失。
- 凭据引用边与配置、历史配置版本在同事务内维护；建立对应外键约束。凭据删除和私钥回收不再依赖全局锁下的事后重建。
- 节点删除继续使用持久化游标和短事务；采样、编辑、删除之间通过节点状态、revision 和资源行锁协调。

**缓存**

- 移除 `cache_generation` 单行计数及按域单行热点，保留原有缓存能力和依赖域划分。
- 详情缓存使用实体版本；列表、概览及目录缓存使用“业务域 × 64 桶”的已提交版本向量摘要。按节点、用户等稳定实体 ID 选桶，禁止高频数据统一落在固定桶。
- 同一事务内合并失效项，按域和桶的固定顺序更新版本；业务数据与版本一起提交。
- 缓存填充使用同一只读快照中的数据及依赖版本，继续遵守证书到期等时间边界。
- Redis 排名更新使用实体版本比较，删除保留版本墓碑，防止迟到消息恢复旧排名。
- Redis、进程内缓存和通知均不是权威来源；通知断连后按数据库版本重建，Redis 不可用时回退数据库。授权、撤销和配额判断始终读取权威状态。

## 3. 多实例任务、采集与事件协议

**实例与资源归属**

- 每次进程启动生成新的 `instance_id`；实例登记仅用于心跳和观测，不限制其他实例启动。
- 新增资源租约及执行代次：记录资源键、所有者、generation、到期时间和关联工作项。默认租约 60 秒、每 10 秒续租，全部以数据库时间判断。
- 通过 `FOR UPDATE SKIP LOCKED` 领取工作；所需资源租约与工作归属在同一事务获取。节点远端工作使用节点资源租约，DNS 变更使用连接／区域资源租约，证书维护按 CA 或身份划分。
- 所有执行进度、完成、失败、清理游标和采样入账必须携带执行上下文并校验 owner、generation；旧执行者不能写回新执行者的结果。
- 删除“启动时恢复所有 running 任务”的行为。恢复器只检查租约过期的工作，不接管其他健康实例。
- 取消和节点移除以数据库状态为准，跨实例通知只用于加速；不得依赖进程内 broadcast 才能停止任务。

**远端副作用**

- 每个外部变更步骤使用稳定操作 ID；发送请求前先持久化 `dispatching` 意图，完成后记录可核验结果。
- 失去续租后停止发送新步骤。数据库租约和 generation 仅保护数据库写回，不宣称能够撤销 SSH 或 DNS 请求。
- 已领取但尚未进入外部发送阶段的工作可以自动恢复；可能已产生副作用的工作进入 `reconciling`。
- 只有确认旧执行者无法继续操作、远端没有未结束的冲突步骤，并核验操作结果后，才允许完成或重试；否则进入 `needs_attention` 并保留资源阻塞。
- 提供重新核验入口，不提供跳过核验的自动解锁。其他节点和资源继续正常运行。

**采集与维护**

- 以数据库时间创建唯一采样周期，冻结该周期的节点集合和预期覆盖数；多个实例共同领取节点采样项。
- 同一节点的远端采集与变更按资源协调；过期周期不追赶补采，缺失按既有统计语义记录。
- 接管时优先继续已落库的采样批次，避免重新采集造成已捕获数据丢失。
- 流量、网络、探测、到期检查、证书续签、CA 轮换、信任清理、历史清理及撤销调度全部纳入可领取、可恢复的工作模型。
- 临时目录、探测文件及下载中间文件按实例／操作隔离；启动清理不得删除其他实例的文件。

**事件发布与客户端**

- 管理 API 升级到 `/api/v2`，旧管理 API 返回 426；现有节点认证回调及用户订阅下载地址保持有效。
- 写请求要求 `Idempotency-Key`，按管理员、操作及请求摘要去重。成功响应与业务事务原子保存；含凭据的响应加密保存，重试返回同一结果。
- `job_events` 作为事务内 outbox，事件通过统一入口在任务行锁内追加。取消“源事件 ID 等于客户端续读顺序”的假设。
- 发布器只读取已提交、尚未发布的事件，使用独立发布序号。多个发布器通过发布流的短行锁协调，每批最多 256 条；该锁只覆盖发布事务，业务写入不等待它。
- SSE 游标改为 `v2:<epoch>:<publication_seq>` 字符串；支持重复投递，以稳定事件 ID 去重，不承诺跨任务的业务提交全序。
- 客户端先取得流头游标，再加载完整状态，随后续读；处理成功后才保存游标。游标失效返回 410 并重新同步，连接可以落到任意实例。
- 更新 OpenAPI、生成模型、版本握手、目录版本摘要，以及 `reconciling`、`needs_attention` 和并发冲突的客户端展示。

## 4. 验证与完成标准

在隔离环境运行三个独立服务进程，共用 PostgreSQL 和 Redis，通过负载均衡交替访问。

必须通过：

- **计费一致性**：跨节点同时记账、重复批次、乱序结果、处理中途崩溃、配额重置及人工修正，结果均与规定的串行参考结果一致。
- **资源互斥**：同节点远端操作、同 DNS 区域变更不会重复领取；无关节点能够并行提交；旧 generation 的迟到写回全部被拒绝。
- **故障接管**：杀死一个实例、暂停进程、断开数据库连接后，数据库内工作恢复；其他健康实例的任务不被重置。
- **远端不确定性**：覆盖请求已执行但响应丢失、旧实例失联、远端不可达等情况；不重放不明操作、不提前释放冲突资源。
- **事件可靠性**：故意让较小源事件 ID 晚提交，仍能发布；发布前后崩溃、断线换实例和重复投递均不漏事件。
- **缓存一致性**：跨实例更新、事务回滚、分桶碰撞、Redis 重启、通知丢失及删除后迟到消息，均不能返回错误版本或恢复已删除实体。
- **业务回归**：节点删除、授权变更、订阅轮换、凭据引用及回收、CA 轮换、部署与卸载全部通过。
- **迁移完整性**：业务表数量、ID、用量及内容校验保持一致；全部历史事件和任务关联仍可查询。

运行相同数据集的单实例与多实例对比，报告吞吐、延迟、锁等待、租约接管、重试和缓存命中情况，不设置未经验证的吞吐承诺。完成标准还包括活动代码中无两把旧锁的调用，运行时无对应 advisory lock；SQLx 的迁移互斥保留。

## 5. 迁移、发布与交付

- 保留现有迁移历史，追加新迁移；迁移回填事件发布序号、缓存版本、凭据引用及必要执行元数据，不清空业务历史。
- 将 schema 及一次性数据迁移集中到 `--migrate-only`。普通实例启动只检查 schema、协议和共享主密钥指纹，不再各自执行初始化改写。
- 切换时停止所有旧实例，保留旧镜像与配置并完成可恢复备份。残留的旧运行任务按副作用情况转为恢复或核验状态，不能统一重新排队。
- 迁移完成后先校验数据，再启动新版多实例及新版客户端；负载均衡不要求粘性会话。readiness 反映数据库和协议就绪情况，Redis 故障允许降级。
- 隔离环境验收三个实例；生产双实例切换前核对总连接数与内存预算，资源不足则暂缓生产扩副本，不以功能正确性推导容量承诺。
- 失败回退使用完整数据库备份、旧镜像和旧客户端；不通过原地降级 schema 混跑版本。
- 服务端、协议／客户端和部署改动分开提交，保留工作区已有的 macOS 模板编辑改动。实施完成后将计划及实际验证结果保存到 `docs/plans/0034-two-lock-removal-and-multi-instance.md`。

### 已落地的第一阶段

- 追加迁移 0041：历史事件按源 ID 回填独立发布序号，保留源事件、任务关联与业务内容。事务内 pending 队列避免扫描全部历史；多个发布器在发布流行锁内每批处理最多 256 条，业务事务不获取发布流锁。进程后台持续发布，SSE 数据额外携带稳定 `event_id`。
- 追加迁移 0042：实例心跳、资源租约及外部操作日志。租约 60 秒、每 10 秒续租，使用数据库时钟，释放后保留 generation。队列领取使用 `SKIP LOCKED`，按排序后的 job／node／DNS 资源键同时获取工作归属。
- 任务执行进入带租约的作用域；`begin_write` 和新事务重试边界在事务内校验 owner、work ID、generation 和租约有效期。续租失败停止本地 future。取消额外轮询数据库状态，不依赖本地广播。
- SSH 命令、SFTP 上传、SSH HTTP 写请求及 DNS 写请求在发送前提交稳定步骤意图；请求明文只存摘要。收到明确完成结果后记录证据。未确认退出状态的 SSH 命令不再当作普通退出码处理。响应丢失、超时或被中断会保留不确定操作，不自动重发。
- 恢复器不再在启动时统一重置 running 任务，只处理租约过期／无归属工作。没有外部发送意图的已领取工作可以重新排队；不确定远端操作和旧版本远端 running 任务转为核验／人工关注，并阻塞相关资源。当前暂用 `status=failed` 加 `stage=reconciling/needs_attention`，正式状态将在 v2 协议阶段统一。
- 新增可重试的 SERIALIZABLE 纯数据库闭包，对 40001／40P01 最多重试五次并随机退避；业务 409 不重试，耗尽映射为 503。已接入撤销义务调度，其余管理变更尚待逐一改造。
- 追加迁移 0043：运行契约保存 schema、协议与共享主密钥指纹。普通启动只检查迁移及校验和和运行契约；凭据迁移、模板初始化、引用初始化、统计初始化集中到 `--migrate-only`。Compose 增加显式 maintenance profile 的 migrate 服务，安装说明已同步。

# 0016 执行收尾与租约监督竞态修复

日期：2026-11-05，Asia/Shanghai。基线 `2a1cb72`。状态：代码与本地验收完成，未部署生产。

本编号沿用本次获选计划；已有同编号的目录重组记录保留，分别使用明确的文件名。

## 问题与范围

生产排查及真实数据库复现确认：完成事务提交业务结果、退出 running 并释放租约后，等待同一行锁的续租可能返回零行。原监督器把这种正常收尾识别为所有权丢失，丢弃业务 future 及其返回值。详见私密运维记录 `production/investigations/20261105-postdeploy/REPORT.md`。

本轮只修复执行收尾交接，按 10 万用户、1 万节点设计。事务隔离级别、串行化 ERROR 的记录边界、采样调度和分钟截止时间不在本轮范围；这些日志不能作为本轮零告警承诺。

## 方案与实际实现

### 与事务尝试绑定的共享生命周期

- 父执行与嵌套身份范围共享 `Active → Committing → Committed`；明确提交失败恢复 Active，提交结果不明进入 RecoveryRequired，真实所有权失效进入 Lost。
- 收尾意图绑定当前生命周期、实际数据库连接、本次事务尝试和捕获的资源凭据（resource/work、owner、generation、epoch）。每次重试有独立意图。
- `db::write`、`db::serializable` 在发出 COMMIT 前发布 Committing，成功回执后立即发布 Committed。超时、连接中断及等待中的提交 future 被丢弃均保留不确定状态，不能返回成功或盲目重试远端操作。
- 提交前使用一条有界集合查询核对实际最终行、当前 epoch、捕获资源及未决远端操作。保存点回滚后的陈旧内存意图不能被提交为收尾成功。
- 不新增 schema、数据库表、迁移或一次性数据迁移工具；HTTP、管理协议及持久业务状态格式保持。内存只随活跃执行及其最多 100 个嵌套身份资源增长。

### 监督器与调用者

- Active 保留启动检查、续租、取消及代际检查。续租结束后再次读取共享生命周期，避免把本次已提交的释放误判成接管。
- Committing 暂停当前续租，继续轮询原提交 future；明确回滚后重建续租与观察。Committed 停止续租并允许原返回值及必要清理完成。
- 提交确认与提交后延续均以当前数据库操作超时为上限。子范围超时将 RecoveryRequired 传播给父范围。
- 内部返回值区分 Returned、Lost、RecoveryRequired；调用者必须显式传播不确定结果。提交后常规写入和网络操作入口拒绝继续工作。
- 特许清理只使用原捕获资源逐项 fencing；不会释放新代际资源。嵌套身份释放不能结束父执行，父执行在子范围中收尾则共享提交结论。

### 接入路径

覆盖维护完成/让出、采样成功/失败/重排队、任务成功/失败/重排队/隔离及 DNS 等待。所有有关租约释放检查布尔结果；未决远端操作仍保留核验与阻塞屏障。增加执行身份、提交尝试、收尾类型和生命周期转换的内部诊断。

主要实现位于 `crates/hysteriax-server/src/execution/{finalization,supervision}.rs`，事务边界位于 `src/db/mod.rs`，生产调用方按新返回值契约接入。

### 验收发现的独立入队时钟修正

连续回归还发现 API 的立即入队使用应用主机时间，而认领比较数据库时间。应用时钟领先时，刚入队的任务会暂时处于未来，测试对立即认领的严格断言得到 None。无休眠的 r6 前四轮通过，第五轮 382 passed、21 failed、3 ignored，21 项均为认领得到 None；当时测得数据库比应用主机约慢 15ms。不能把该轮也解释为休眠，亦不能归入收尾状态机。

在归档基线副本中仅将 `api::now()` 前移 2 秒后，同一 SSH 测试在同一认领断言失败；明确标识为基线加时钟故障注入，不称为未修改基线失败。时钟对齐时，原始基线及冻结版本各三次该用例均通过。证据位于 `target/execution-finalization/claim-attribution/`。

本轮同时做最小修正：立即入队的 available_at、created_at、updated_at 使用单条 INSERT 内同一个数据库时间，queued 事件复用 RETURNING 时间，不增加 SQL 往返。新测试通过任务局部的测试时钟模拟 ±120 秒偏差，要求立即任务可认领且事件时间一致；另断言明确延后 30 秒的任务仍不可认领。没有更改认领测试助手、放宽现有断言或调整采样调度、截止时间与退避时长。

## 已调查的验证问题

1. 新监督包装曾使深层 mTLS future 触发默认测试栈溢出；将监督器持有的 future 放到堆后，该用例在默认测试栈通过。另一模板下载用例在未修改基线同样默认栈溢出，保留基线/当前日志；后续使用项目现有性能验证采用的 16 MiB 测试线程栈，生产运行配置不变。
2. 身份接管测试原先强制解包旧返回值。共享生命周期现在明确传播 Lost；断言只接受 Lost 或业务拒绝，仍要求迟到写入为零且替代执行租约保留，不接受成功或 RecoveryRequired。
3. 新故障夹具原设 100ms 锁等待和 2s 通用协调预算，并假设释放后首次 SKIP LOCKED 认领必成功。改为项目正常 1s 锁等待、20s 有界协调及有界重试；刻意测试的 250ms 提交超时保持。
4. 大规模删除在磁盘隔离运行中既有通过也有 30s worker 超时。未修改基线与当前版本隔离对照分别约 41.45s、38.51s 总用时，均通过；不能声称基线复现同一次超时。活动采样捕获 COMMIT 的 WalSync 等待。在内存盘且 fsync/synchronous_commit 开启的同配置对照，两者分别约 27.93s、27.96s，总体断言通过。重复功能回归使用明确记录的内存盘环境；容量测量单独使用磁盘数据库。
5. 初始 DNS 过滤器使用物理目录名未匹配逻辑测试命名空间，被零匹配检查拒绝；已修正，未将该运行计为通过。
6. 冻结源码的 r5 前 7 轮各 404 passed、3 ignored。第 8 轮期间主机因低电量休眠约 7 小时 18 分钟（内核记录 11:44:27～19:02:43），测试跨过真实租约和超时窗口后出现集中失败，最终 347 passed、56 failed、3 ignored；该组不算连续验收。失败包括连接池超时、认领未取得工作和租约失效，不能以受中断运行判断各业务路径的正确性。`target/execution-finalization/{host-sleep,sleep-failures,post-sleep-clock}.json` 保存时间、失败及恢复后的时钟核对证据。接通电源后，在仅覆盖本轮验证进程生命周期的防闲置休眠断言下重新执行完整验收，不改产品超时或测试断言。

原始失败、预检和最终结果分别保留在 `target/execution-finalization/`，不将 smoke、中断或源码变化的轮次纳入正式验收。

# 0032 可恢复的分批节点删除

> 后续真实业务节点暴露了索引执行计划与写锁争用问题，修正和最终验收见
> [0033 节点清理索引与断点恢复](0033-node-cleanup-index-plan.md)。

## 目标

恢复大量历史数据下的节点删除功能。原有记录删除由 HTTP 请求持有一个大事务，
客户端超时后回滚；连接池隔离只能保护其他读取，不能让删除成功。

## 已实施

1. 超过 1,000 条历史/汇总记录时，记录删除返回 HTTP 202 并排入持久化
   `record-remove` 任务。小数据量继续同步返回 204；现有客户端接受这两种成功响应。
   重复请求复用活动任务，失败后重新请求建立关联重试。
2. 节点进入 `deleting` 状态，停止新采样及其他节点操作。保留原有修订号、远端操作、
   DNS 与托管 mTLS 检查；记录删除任务不连接 SSH、不宣称远端卸载成功。
3. 原始样本和汇总按游标分批清理，初始每批 512 条。每条清理 SQL 限时 2 秒，
   超时减小批量，最小 32 条。每批独立提交进度并短暂让出写锁；普通清理仍维护统计，
   只有经过删除状态验证的清理事务跳过即将删除的节点汇总更新。
4. 在线样本按批刷新派生统计，避免积累一次巨大的汇总事务。最终短事务完成元数据、
   审计和任务成功状态的原子提交。最终级联查询强制定制计划并抑制顺序扫描，避免按旧统计
   再次扫描已经清空的节点历史；最终删除 SQL 同样限时。
5. 任务重启后继续剩余数据；取消任务不发出节点已删除信号。远端卸载成功后的本地历史
   清理也使用相同批处理路径。客户端源代码补充任务阶段、清理数量和删除状态文案。

## 验证

- 新增完整删除、幂等提交、其他写入可用、其他节点数据保留、中断恢复、失败关联重试、
  仅剩大量汇总记录及取消信号回归。
- 队列、节点删除、统计、鉴权、远端卸载/DNS、部署及托管信任删除限制相关回归通过。
- 节点任务反馈、显示文案和 1,951 项双语资源校验通过。
- 在明确命名的本地生产数据副本上，通过 HTTP 接受真实规模删除：约 55 毫秒返回 202，
  约 79 秒完成约 49 万条历史及汇总记录清理。期间 381 次就绪检查和 381 次写锁获取检查
  成功；最大就绪延迟约 71 毫秒，其他节点各历史表记录数量保持一致。
  此项为默认忽略的显式副本验收测试，拒绝操作名称不以 `hx_readyz_repro_` 开头的数据库。

## 部署

本地构建 Linux amd64 镜像 `hysteriax-server:node-cleanup-20261021` 后传到服务器。
镜像仅包含已提交基线与本次服务端修复、前次隔离修复和相关 API 文档变更。
部署前保存环境配置和统计触发器函数定义，部署后验证迁移 0039、容器健康及临时节点端到端删除。

线上验收已通过：迁移 0039 成功，容器健康，服务器二进制 SHA-256 与本地一致。
临时节点包含 9,024 条原始样本；删除请求约 1.76 秒返回 202，随后任务成功完成，
共清理 9,174 条历史及汇总记录，数据库记录的任务执行时间约 4.05 秒。
轮询在接受请求后约 16 秒确认节点已消失，
4 次公网就绪检查均为 200。临时用户和所有测试历史已清理，现有业务节点未删除。

## 边界

大数据删除是后台操作，节点会保持删除中直至任务成功。已提交清理不会因客户端退出或
后续失败而恢复；失败任务可继续重试。记录删除仍保留作业历史和审计，不修改其他节点或用户计费。

# Implementation status for `0001_plan.md`

| Stage | Status | Evidence |
|---|---|---|
| P0: Engineering foundation | Implemented | Git, Rust workspace, SwiftPM macOS app target, CI, Compose/Caddy, OpenAPI, build/run entry, and secret setup script exist. The target builds locally. |
| P1: Management service | Implemented | Admin token lifecycle, encrypted secrets, optimistic revisions, CRUD/assignment/resource APIs, persisted jobs and events, resumable SSE, audit, subscription output, HTTP auth, and API version negotiation are wired. Before applying pending migrations to a non-empty SQLite database, startup writes a verified snapshot with mode-restricted permissions; migration acceptance confirms a version-0001 snapshot remains readable while the live database upgrades through version 0004, and a fresh install creates no empty snapshot. The usage API returns per-node sample times, aggregate freshness and gap counts, and pending or failed kick jobs per assigned node. Aggregate freshness becomes stale if any assigned node has missing or old samples, so a fresh sample on one node cannot mask missing data on another. Deployment jobs persist phase changes and redacted progress entries atomically with `job.progress` events; failure details are scrubbed against saved node and user credentials, configured passwords and URL credentials, ACME provider values, and mTLS certificate/private-key material before storage or return. Startup requeues interrupted jobs and writes recovery events atomically; database and process-level restart checks verify recovery, event persistence, worker claim, and retrieval of a progress log after restart. The auth-isolation verifier creates a token with a 100-character Unicode label, uses it, confirms list responses omit token values, revokes it, and verifies it is rejected. The verifier also sends two simultaneous edits at one expected revision and confirms exactly one succeeds while the other receives HTTP 409. OpenAPI generates Swift request and response DTOs and binds every operation to its request/response types, method, path, and required query parameters. The generic API transport and dynamic JSON value codec remain shared handwritten components; regeneration drift is checked in CI. |
| P2: Configuration model | Implemented with compatibility gaps | Fixed-version root and nested field allowlists, type/range/duration checks, encrypted resources, certificate/private-key PEM parsing and uploaded pair matching, YAML generation, managed auth/stats, and native controls for supported TLS/ACME/QUIC/bandwidth/obfuscation/resolver/sniff/ACL/ordered-outbound/masquerade settings are implemented. Server certificate and private-key resources are parsed as PEM, and matching uploaded pairs are verified before sync is queued. mTLS has per-assignment encrypted credentials and resource-backed CA configuration. ECH uses an uploaded encrypted ech_key resource; the server receives its private key and subscriptions extract the public ECH config list. Real Hysteria and Mihomo v1.19.31 TCP transfers passed with mTLS, ECH, Gecko, and port hopping enabled. Realm mode stays rejected after a self-hosted rendezvous probe registered the server and passed the Hysteria client transfer, but Mihomo v1.19.31 timed out on its Realm connect request; a similar timeout is reported for [Mihomo issue 2863](https://github.com/MetaCubeX/mihomo/issues/2863). Enabled Mimic remains blocked. |
| P3: Deployment and sync | Partial; arm64 matrix and Debian 13 live-verified | Pinned binary hash validation, bounded retries for transient asset-download failures, SSH host key confirmation, supported OS checks, SFTP upload, systemd install, per-node serialization, drift detection, health checks, and rollback are implemented. Before marking a deployment successful, the worker runs the pinned Hysteria client and sends a TCP-forwarded HTTP request through the node. By default it targets the local statistics API; mTLS probes require at least one assigned client certificate. Each node can specify an optional HTTP `proxy_probe_url` for a destination allowed by its ACL/outbound policy. If no target is configured and those rules block loopback statistics, the worker confirms an authenticated Hysteria client session without claiming a payload transfer. Temporary probe credentials are hashed, expire after 15 minutes, and are removed after each job. First installs preflight the primary UDP port; port-hop nodes also require nftables/iptables and receive `CAP_NET_ADMIN` only in their systemd unit. Disposable Debian 13 arm64 root/private-key deployments reached the Hysteria traffic and online APIs, carried real TCP and UDP proxy traffic, and uninstalled cleanly. The expanded arm64 systemd matrix passed Debian 12/13 and Ubuntu 22.04/24.04 with root/key, sudo/key, and sudo/password SSH access on every image, including the client probe. Live failure probes verify wrong SSH fingerprints, refusal of an unmanaged remote directory, occupied-UDP preflight rejection before remote installation followed by successful retry, SSH interruption during deployment followed by retry and recovery, an injected service-start failure that restores the prior config, and a health-check failure whose automatic rollback restart is forced to fail; explicit sync recovers both rollback cases. A Rust unit test confirms downloaded bytes with a mismatched pinned SHA-256 are rejected before installation. Native amd64 and independent cloud-VM coverage remain. The native amd64 matrix workflow is added but has not run; local QEMU did not provide reliable amd64 service-health evidence. |
| P4: Users and subscriptions | Partial; deployed two-node arm64-container acceptance passed | User creation and editing (name, enablement, expiry, and quota), node assignment, independent credentials, expiry/quota authentication, subscription rotation, non-rotating current-link copy, local Mihomo YAML export through the current token, empty-safe Mihomo YAML, and kick/online checks are wired. API integration checks cover clearing a quota, expired and over-quota auth denial, and 403 subscriptions. Live Hysteria and Mihomo v1.19.31 clients authenticated through the callback, downloaded subscriptions, transferred TCP data, completed a SOCKS5 UDP echo, and connected with mTLS, ECH, Gecko, and port hopping enabled. A deployed two-node/three-user run verified cross-node assignment denial and shared-user traffic. Live acceptance kept two Hysteria clients streaming through natural expiry, explicit disable, and over-quota; each event kicked both devices, denied new auth, returned zero online connections, blocked further traffic, and returned HTTP 403 for the subscription. A separate active credential-rotation case kicked both old sessions, denied the old credential, accepted the replacement, and verified the existing subscription now contains the new credential. Realm mode remains rejected by the compatibility gate. Native cloud-VM two-node acceptance remains. |
| P5: Quota controls | Implemented; single-node and two-node-container live-verified | Ten-second SSH sampling, instance IDs, per-node baselines, transactional delta accumulation, quota reset, expiry/overage kick scheduling, and gap records are implemented. Live tests sampled traffic from one user on two deployed nodes, enforced the aggregate measured quota on both callbacks, and received one kick job per node. Database tests cover duplicate samples, late samples applied after reset, restart counter-baseline gaps, quota-reset revisions, and malformed responses that must create a data gap without partially charging usage. A live SSH outage test verified usage stayed unchanged while unreachable, the gap opened once across repeat failures, 2 MiB transferred during the outage was charged after SSH returned, and another sample did not double-charge it. |
| P6: Client and release | Partial | Native Xcode project builds a universal arm64/x86_64 app with a macOS 26 deployment floor so the Intel slice remains usable on the final Intel-compatible macOS release; macOS 27 and later run the native Apple silicon slice. CI and the release script run `scripts/verify-macos-app.sh` to check both slices and their minimum deployment versions. Keychain settings, SSH trust, supported configuration fields, resource import, user assignment, credentials/subscriptions, tasks, and audit list work. Settings creates and switches to a one-time administrator token, stores it in Keychain, marks it as the current Mac token, and prevents revoking that token while allowing older tokens to be revoked. The Users detail panel refreshes every 15 seconds and shows per-node sample times, fresh/stale/not-collected status, open gap counts, and queued/running/failed revocation jobs. The Nodes table shows each node's last sample, freshness, unresolved gaps, and queued revocations; the Overview counts nodes needing attention. Live sampling recovery checks confirm the node-level sample timestamp and freshness advance when SSH returns. The list views support search and column sorting, timestamps render in the Mac's local time zone, and primary creation actions use Command-N. The Users screen copies the current subscription URL without rotating it and exports the current Mihomo YAML. Task updates use resumable SSE with a persisted per-service event cursor and periodic usage refresh; task results identify whether the Hysteria deployment probe transferred TCP data or only confirmed an authenticated session under custom routing rules. The task detail view fetches persisted phase logs and offers retry actions for failed SSH tests, deployments, syncs, and rollbacks. Per-service node, user, job, and audit display snapshots persist with their update time; reads requiring server details and all mutations are blocked while disconnected. Backup/restore commands verify SQLite integrity, archive file hashes, path safety, and matching master-key fingerprints; archive unit tests and `scripts/verify-backup-restore-compose.py` cover isolated stop/archive/restore/readiness. Tag-triggered Developer ID/notarization workflow signs and publishes a notarized direct-distribution DMG, while the GHCR multi-architecture image workflow publishes server images; neither workflow has published artifacts in this checkout. Signed-release acceptance remains. |

The live deployment used disposable Debian 13 arm64 systemd containers. TCP, UDP, mTLS, two-node/three-user isolation, two-client active revocation for natural expiry, disable, over-quota, and credential rotation, aggregate two-node quota enforcement, deployment retry/rollback failure probes, deployment-time Hysteria client TCP probing, and quota-sampling outage recovery passed with real clients. The arm64 systemd-container matrix passed for Debian 12/13 and Ubuntu 22.04/24.04 with root/key, sudo/key, and sudo/password SSH access on all four images. The checksum mismatch guard is covered by a Rust unit test. Native amd64 runner acceptance, independent cloud-VM validation, and signed/notarized publishing still need to run in their respective environments.

The deployment probe's custom-route handling is acceptance-tested with `direct(all)` and an explicit loopback-reject ACL: it transfers TCP when the test destination is permitted, and reports an authenticated session when the configured policy blocks that destination. Custom policies that require a data-transfer probe still need a configurable reachable target.

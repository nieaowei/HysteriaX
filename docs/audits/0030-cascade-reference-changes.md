# 0030 订阅编辑器级联变更

日期：2026-10-20。

## 重命名

- 对象列表内编辑 `tag` / `name` 时，自动同步所有已识别的引用，不再要求手工先解除引用。
- sing-box 覆盖入站、出站、DNS 服务器、规则集、HTTP 客户端、证书提供者、网络命名空间；端点按出站目标同步，和服务端现有引用索引一致。
- 支持规则集多标签的单项重命名。其他标签保持原值；不能把一个已引用的标签直接改为空而留下失效引用。
- Mihomo 支持代理组名称及原生规则目标；规则集和命名子规则的底层引用变换也按各自语义实现。现有菜单的规则集重命名仍走服务端重构入口。
- 同步路由 / DNS 默认目标、对象之间的依赖以及动态节点注入组；普通域名、URL、密码及无引用元数据的未知字段保持原值。
- 检查目标名称冲突、保留前缀及 Mihomo 分隔符，不会覆盖另一个对象。同一笔名称和引用更新只增加一次撤销记录。

## 级联删除

用户明确选择“删除对象及依赖它的规则”。有依赖时，原草稿保持不变，先展示预览；点击“级联删除”后才提交到本地草稿。

| 引用位置 | 处理方式 |
| --- | --- |
| 路由 / DNS 规则，含嵌套逻辑条件 | 删除整条外层规则，避免移除条件后扩大匹配范围 |
| Mihomo 原生规则、命名子规则中的规则 | 删除对应完整规则；空的命名子规则继续触发调用者级联 |
| 代理组成员列表 | 移除对应成员；清除引用它的默认成员。静态成员耗尽且无注入规则时，删除该组并继续处理依赖 |
| 其他命名对象的依赖 | 删除该依赖对象并继续计算后续引用，避免留下不完整配置；具体对象列入预览和完整差异 |
| 全局默认出站、DNS、HTTP 客户端等 | 清除相应字段；全局域名解析器的服务器引用失效时移除整个解析器对象 |
| 动态节点注入目标组 | 删除对应注入规则 |

预览显示操作前的路径，并可展开完整 JSON 差异；移除前面的数组项后，会把后续对象的预览路径映射回操作前位置。确认时检查草稿和编辑层仍与预览基线一致；草稿已变化则拒绝应用旧预览。取消不写入，确认后的全部删除与引用处理可以一次撤销 / 重做。

## 平台与边界

- 统一配置只修改共同配置，不生成无意义的平台覆盖。
- 旧版共同配置会同步检查实际存在的平台覆盖；写入差异时保持其他继承关系，数组继续遵守整体覆盖语义。
- 旧版单平台中，被全局注入规则引用的组不允许单独重命名，提示先转换统一配置，防止其他平台的全局注入目标失效。正常工作台已要求先处理多平台配置转换。
- Mihomo 逻辑匹配表达式按结构遍历，只识别真正的 `RULE-SET` 条件；正则表达式里形似 `RULE-SET,A` 的文本不当作引用。
- 级联处理已有引用元数据和受支持的原生规则语法，不猜测未知扩展字段。发布仍使用原有校验流程。
- 未知协议或动作分支保持原值，不根据编辑器兜底分支猜测其字段含义；这类未验证配置中的额外引用不自动级联。
- 端点文档：[端点具有入站与出站行为](https://sing-box.sagernet.org/zh/configuration/endpoint/)；本次出站引用覆盖与服务端 `catalog.rs` 中端点注册逻辑保持一致。

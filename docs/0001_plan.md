# HysteriaX 完整实施计划

## 1. 项目目标与架构

建设一套自托管的 hy2 节点与用户管理系统，完成“配置节点 → SSH 部署 → 自动同步 → 分配用户 → 发布订阅 → 执行到期与配额”的完整流程。

采用三个部分：

| 部分 | 技术与职责 |
|---|---|
| macOS 管理客户端 | SwiftUI 原生界面，负责配置编辑、操作发起、任务进度和状态展示 |
| 常驻管理服务 | Rust，保存数据，执行 SSH 部署、认证、流量统计、配额控制和订阅生成 |
| hy2 节点 | 官方 Hysteria 2 二进制与 systemd 服务，承载实际代理流量 |

客户端通过 HTTPS 管理 API 连接 Rust 服务；服务通过 SSH 管理节点。节点向管理服务请求用户认证，订阅使用者直接访问 HTTPS 订阅地址。关闭 Mac 不影响部署任务、认证、配额和订阅。

首版固定兼容基线为 [Hysteria 2 v2.12.3](https://github.com/HyNetworks/hysteria/releases/tag/app%2Fv2.12.3) 和 [Mihomo v1.19.31](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.31)。发布后通过经过测试的版本清单扩展支持，不自动跟随上游最新版。

## 2. 功能与实现设计

### 管理服务与数据模型

采用 Rust workspace，按领域逻辑、配置生成、SSH 部署、持久化、HTTP API 分离模块。使用 Tokio、Axum、SQLx/SQLite、Serde、russh 与 SFTP；数据库启用 WAL，并提供版本化迁移。

服务端是唯一权威数据源。SwiftUI 客户端保存连接设置和展示缓存，不复制认证、配额和配置生成逻辑，也不需要 Rust FFI。

| 实体 | 必须保存的内容 |
|---|---|
| 节点 | UUID、名称、SSH 连接信息、主机指纹、公网连接参数、运行状态 |
| 配置版本 | 期望配置、成功部署配置、版本号、内容摘要、资源文件引用 |
| 用户 | UUID、名称、启停状态、到期时间、总额度、累计用量 |
| 节点分配 | 用户与节点关联、独立 hy2 凭据、可选客户端证书 |
| 订阅凭据 | 用户关联、令牌摘要、加密令牌、轮换及撤销状态 |
| 流量记录 | 节点运行实例标识、用户计数基线、累计增量、采集时间 |
| 后台任务 | 类型、目标版本、执行阶段、结果、重试状态、脱敏日志 |
| 审计记录 | 配置修改、部署、撤权、密钥轮换和额度重置 |

配置保存与同步任务入队在同一数据库事务中完成。节点、用户更新携带 `expected_revision`，版本冲突返回 `409`，防止多台 Mac 覆盖彼此的修改。

### 节点配置与完整字段表单

- SSH 表单包含地址、端口、用户名、密码或私钥、私钥口令、固定主机指纹；支持 root 和免交互 sudo。
- 首次连接先展示主机密钥指纹，由管理员核对并保存；后续指纹变化时停止连接。
- 区分 SSH 地址、hy2 对外地址、监听地址和 TLS SNI，避免将内网地址写入订阅。
- 以固定版本的官方配置定义建立字段清单，覆盖监听、Realm、TLS/ACME、ECH、混淆、QUIC、Mimic、带宽、拥塞控制、测速、UDP、认证、DNS、嗅探、ACL、出站、统计和伪装。[字段依据](https://v2.hysteria.network/zh/docs/advanced/Full-Server-Config/)
- 所有字段都有原生控件、说明、默认值和校验；列表、映射及不同 `type` 的子配置使用相应编辑器。提供只读 YAML 预览，不以 YAML 编辑器替代完整表单。
- 认证和统计字段展示为系统托管值，不能覆盖。Mimic 等未通过订阅兼容验证的功能展示限制原因并禁止启用。
- 证书、私钥、ECH 密钥、ACL 和 Geo 数据等配置资源支持上传并引用；秘密文件加密保存，部署时设置必要的文件权限。
- TLS 与 ACME 互斥；校验端口、带宽单位、超时、窗口范围、资源依赖及功能组合。后台执行最终校验，客户端提供即时反馈。
- ECH、Realm、Gecko、端口跳跃和 mTLS 分别建立兼容用例。启用 mTLS 的节点必须为分配用户提供匹配的客户端证书和私钥，订阅携带客户端所需内容。

### SSH 部署与自动同步

首版支持 Debian 12/13、Ubuntu 22.04/24.04，架构为 amd64、arm64，只管理 HysteriaX 新安装的实例。

部署流程固定为：

1. 检查系统、架构、systemd、sudo 权限、端口、磁盘和已有实例。
2. 下载固定版本官方二进制，校验发行资产摘要，再通过 SFTP 上传。
3. 创建项目专用目录、服务账户、配置资源和 systemd unit。
4. 写入临时配置，执行结构与资源校验，备份当前成功版本。
5. 原子替换配置，启动或重启服务。
6. 检查服务、认证与统计接口，并使用官方客户端完成实际代理连接探测。
7. 成功后记录已部署版本；失败则恢复上一成功版本并重新检查。

不使用未经固定版本和校验的远程安装脚本；官方安装脚本本身也不承担完整配置与启动流程。[安装说明](https://v2.hysteria.network/docs/getting-started/Server-Installation-Script/)

自动同步行为：

- 保存配置后自动排队；同一节点串行执行，不同节点允许并行。
- 未执行的旧版本任务可以被新版本替代；已经执行的任务完成后再应用最新版本。
- 记录“期望版本”和“已部署版本”，展示同步中、失败、已回滚和配置漂移。
- 检测远程配置摘要变化；发现人工修改时暂停自动覆盖，允许管理员显式重新应用期望配置。
- 对连接故障进行有限重试；配置错误停止重试并提供具体错误。
- 服务重启后先核对远端状态，再恢复未完成任务，避免重复安装或错误覆盖。
- 订阅始终使用成功部署版本。新节点部署成功前不进入订阅；暂时不可达的已部署节点保留，并标记状态。
- 遇到非 HysteriaX 实例或资源冲突时停止，不自动接管。

### 用户、认证、到期与配额

用户支持新增、编辑、删除、启停、节点分配、到期时间、总流量额度、用量查询、额度重置和凭据轮换。

采用 hy2 HTTP 认证：

- 每个节点使用独立认证令牌访问管理服务。
- 每个用户在每个节点拥有独立随机 hy2 凭据。
- 后台检查节点分配、用户状态、到期和额度，再返回稳定的用户 UUID 作为统计身份。
- 用户改名不改变统计身份；增删用户和修改分配无需重启节点。
- 禁用、删除、到期、超限或取消节点分配时，先拒绝新认证，再持续请求踢下线并检查在线状态。[认证协议](https://v2.hysteria.network/zh/docs/advanced/Full-Server-Config/)

配额规则：

- 按用户汇总所有节点的上传与下载字节，采用总额度和手动重置，不自动按月结算。
- 每 10 秒通过 SSH 通道访问节点本地统计接口；统计接口只监听 loopback，并设置独立密钥。
- 使用不清零的 `/traffic` 累计计数计算增量，基线与用户累计量事务性写入，避免重试重复计费。
- 使用 systemd 运行实例标识识别 hy2 重启；采样前后检查实例一致性，避免跨实例计数混用。
- 超限后拒绝认证并调用 `/kick`；请求成功不视为全部设备已断开，继续检查并处理剩余连接。[统计接口](https://v2.hysteria.network/zh/docs/advanced/Traffic-Stats-API/)
- 手动重置开始新的额度周期，保留历史记录和节点采集基线；按重置时已入库用量划分，迟到采样计入新周期。
- 管理服务不可用时拒绝新连接；已有连接可能继续传输，恢复后补统计和撤权。
- 接受采样窗口内的超额。hy2 异常退出可能丢失尚未采集的内存计数，必须记录统计缺口并展示数据新鲜度，不将其作为精确计费账本。

### 订阅与配置输出

订阅令牌与 hy2 认证凭据独立生成和轮换，使用至少 256 位随机值。

- 提供 HTTPS 在线订阅和本地 YAML 导出；两种方式使用同一生成器。
- 订阅只包含用户已分配、已启用且成功部署的节点。
- 明确输出目标为 Clash Meta/Mihomo，不承诺兼容不支持 hy2 的旧版 Clash。
- 映射地址、端口、认证密码、SNI、证书验证、混淆、带宽，以及经过验证的 ECH、Realm 和端口跳跃参数。[Mihomo 字段依据](https://wiki.metacubex.one/config/proxies/hysteria2/)
- 固定提供完整配置模板：本地 `mixed-port`、禁止 LAN 访问、节点选择组、`DIRECT` 选项和默认 `MATCH` 规则；首版不引入外部分流规则订阅。
- 使用 UUID 派生后缀解决节点重名，并对 IPv6、特殊字符和 YAML 字符串进行正确编码。
- 未分配节点时仍输出可解析的空代理配置，使用 `DIRECT`，界面明确提示。
- 无效或已撤销令牌返回 `404`；禁用、到期和超额用户返回 `403`。成功响应使用 `Cache-Control: no-store`。
- 轮换订阅令牌只撤销旧订阅地址。需要撤销已经下载的配置时，使用独立的 hy2 凭据轮换并清理旧连接。

### 原生 macOS 界面

最低支持 macOS 27，提供 Apple Silicon 和 Intel 构建，首版使用中文界面。

采用 `WindowGroup` 主窗口和独立 `Settings`，以 `NavigationSplitView` 组织概览、节点、用户、任务和审计；详情采用表格、表单和检查器。

必须完成的操作流程：

- 首次连接：输入管理服务 HTTPS 地址和管理员令牌，验证连接并保存到 Keychain。
- 节点：创建、SSH 测试、指纹确认、完整配置、部署、同步、回滚和状态检查。
- 用户：编辑权限、到期和额度、分配节点、查看用量、复制订阅、导出配置和轮换凭据。
- 任务：查看阶段进度、日志、失败原因和可重试操作。
- 服务断开：展示缓存与更新时间，禁止提交写操作；恢复后重新读取服务端状态。
- 支持搜索、排序、键盘操作、系统明暗主题和辅助功能标签。

## 3. API、凭据与运维接口

管理 API 使用 `/api/v1`，统一 JSON、UUID、UTC 时间和结构化错误。管理员使用可轮换 Bearer Token；长任务返回 `202` 与 `job_id`，进度通过 SSE 获取，断线后可恢复。

| 接口组 | 能力 |
|---|---|
| `/nodes` | 节点增删改查、配置版本与状态 |
| `/nodes/{id}/ssh-test` | SSH 测试、主机指纹与环境检查 |
| `/nodes/{id}/deploy`、`sync`、`rollback` | 创建异步部署、同步和回滚任务 |
| `/users` | 用户、到期与配额管理 |
| `/users/{id}/assignments` | 节点分配与撤销 |
| `/users/{id}/subscription` | 查询及轮换订阅凭据 |
| `/users/{id}/credentials/rotate` | 撤销旧 hy2 凭据并生成新凭据 |
| `/users/{id}/usage`、`quota/reset` | 用量查询和手动额度重置 |
| `/jobs/{id}`、`/events` | 任务结果、日志与事件流 |
| `/sub/{token}/clash.yaml` | 公开订阅下载 |
| `/hy2/auth/{node_id}/{node_token}` | hy2 认证，按官方请求与响应格式实现 |
| `/healthz`、`/readyz` | 存活、数据库和启动状态检查 |

使用 OpenAPI 生成 Swift 数据模型与客户端接口，并在 CI 检查契约一致性。

部署使用 Docker Compose：Rust 服务、Caddy HTTPS 反向代理和持久化卷。管理员提供域名、DNS、数据库加密主密钥及初始管理员令牌。

- SSH 密码、私钥、hy2 密码和证书私钥使用带认证加密保存；主密钥通过服务端秘密文件提供，不写入数据库。
- 管理员、节点认证和订阅令牌分别管理；令牌校验使用摘要，需再次展示的订阅令牌另存加密副本。
- HTTP、任务和代理日志均屏蔽令牌路径、密码及私钥。
- 提供数据库一致性备份、资源备份和恢复命令；主密钥必须独立备份。
- 数据库迁移前备份；服务端与客户端提供 API 兼容版本检查。
- 展示节点最后采集时间、同步失败、待撤权连接和统计缺口，避免将陈旧数据展示为正常状态。

## 4. 实施顺序与阶段交付

| 阶段 | 主要交付与完成条件 |
|---|---|
| P0：工程基础 | 初始化 Git、Rust workspace、Xcode 工程、CI、Compose、OpenAPI；建立统一构建运行脚本和 Codex Run 入口 |
| P1：管理服务 | 数据库迁移、秘密存储、管理员认证、节点及用户 API、持久任务、事件流；重启后数据和任务可恢复 |
| P2：配置模型 | 固定版本字段清单、全部原生表单描述、后台校验、资源管理、YAML 生成和兼容限制；每个字段都有覆盖用例 |
| P3：部署同步 | SSH、指纹验证、环境检查、安装、健康探测、回滚、漂移检查；完成两种架构的新节点部署闭环 |
| P4：用户与订阅 | HTTP 认证、节点分配、在线订阅、导出和两种凭据轮换；两节点多用户隔离正确 |
| P5：配额控制 | 流量增量累计、到期、超限撤权、重置、断线恢复和统计缺口；多节点配额行为符合约定 |
| P6：客户端与发布 | 完整管理流程、任务日志、离线状态、备份恢复文档、Universal App 和版本化服务镜像；端到端验收通过 |

客户端界面随 P1–P5 接入对应能力，P6 完成整体体验和发布验证。

实施时补齐项目 README、架构说明、安装说明、字段覆盖清单、备份恢复指南和故障排查文档。公开 macOS 发行包通过 DMG 在 Mac App Store 之外直接分发，使用 Developer ID 签名与公证；本地开发构建不依赖发行凭据。

## 5. 验证、验收与固定边界

### 必须通过的验证

- **字段覆盖**：官方固定版本字段逐项对应类型、控件、校验、序列化和兼容状态；覆盖互斥配置、缺失资源和敏感字段。
- **部署矩阵**：Debian 12/13、Ubuntu 22.04/24.04 的 amd64/arm64 VM；测试 root、免交互 sudo、密码与私钥认证。
- **失败恢复**：错误主机指纹、已有实例、端口占用、下载校验失败、SSH 中断、服务启动失败、回滚失败和后台重启。
- **实际代理**：真实 hy2 与 Mihomo 验证 TCP/UDP，以及混淆、端口跳跃、ECH、Realm 和 mTLS 支持组合；配置解析通过不能替代连接测试。
- **权限隔离**：至少两个节点、三个用户；验证未分配节点拒绝认证，改名不影响统计，撤销和轮换使旧凭据失效。
- **配额统计**：重复采样、后台重启、多节点并发流量、节点重启、计数下降、手动重置和采集失败；不得重复累计或产生负增量。
- **连接撤权**：同一用户多个客户端同时在线，禁用、到期和超限后拒绝重连，并持续处理现有活跃连接。
- **订阅一致性**：配置同步失败后仍使用上一成功版本；覆盖无节点、重名、IPv6、特殊字符和禁用用户。
- **客户端与运维**：多台 Mac 编辑冲突、SSE 重连、Keychain、离线展示、备份恢复、升级迁移和日志脱敏。

最终验收流程是：从空服务器部署管理服务，在 Mac 创建两个节点并完成一键安装，创建并分配用户，导入订阅到 Mihomo 验证连接，修改节点配置验证自动同步，再验证到期、超额和凭据轮换。关闭 Mac 后，上述常驻能力继续工作。

### 固定默认值与范围

- 单管理员、单管理服务实例、SQLite；支持多台 Mac，不建设多租户、RBAC 或高可用集群。
- 首版不内置本机代理、系统代理或 TUN，不提供用户登录门户和支付计费。
- 不接管外部 hy2 实例，不提供非托管节点模式。
- 管理者预先配置域名、云安全组及必要的 SSH、UDP 和 ACME 端口；首版不自动改写系统防火墙。
- 使用管理服务 UTC 时间判断到期，客户端按本地时区显示。
- 保留按周期采样的配额语义；严格硬配额、异常退出零丢失计量和月度结算不属于首版。
